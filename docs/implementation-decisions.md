# Decisiones de implementación — 2026-10-26

El pedido actual autoriza implementar el PDF sobre el proyecto existente. Los documentos adjuntos se usan como requisitos de entrega; las restricciones antiguas de detenerse en preparación no sustituyen este pedido. Se conserva la planeación histórica y se documentan aquí las decisiones necesarias para una ejecución local verificable.

1. **Contrato especializado sobre ejemplo del anexo.** Se implementan las 14 operaciones del OpenAPI previo, sin alias `/api/v1/policy/evaluate`. Los DTO especializados y las tablas originales prevalecen sobre el ejemplo genérico del PDF. `model_ref` resuelve VRAM mínima del catálogo. Tres historias del anexo mapean a varias historias previas; los IDs no son intercambiables.
2. **Stack.** TypeScript estricto y Node >=22.18 (native type stripping and `node:sqlite`); HTTP y SQLite nativos. El PDF propone Express/Fastify, Zod y ORM, pero las firmas y SQL acordados ya existen. Se usa el adaptador SQLite con sentencias preparadas y validación explícita; no se añadieron paquetes de ejecución. Es una desviación explícita del stack ilustrativo, que conserva Ports & Adapters. YAML, TypeScript, Vitest y fast-check ya estaban en el lockfile. `lint` es un control estático propio de tipos, límites e impurezas, no una corrida de ESLint.
3. **Tiempo.** Simulación fija configurable por entorno y ventana nocturna 22:00–06:00 UTC−05. La vista previa permite reloj alternativo solo con flag y rol. El perfil fijo no afirma validar NTP ni otras zonas/DST. El límite de 30 ms se mide sobre el núcleo puro caliente, no sobre HTTP y disco.
4. **Durabilidad.** Responder después del COMMIT. Clave calculada por JSON canónico de todo el pedido, incluyendo `exam_binding` y `derived_from`. Replay reconstruye la decisión original desde las filas, no vuelve a consultar las fuentes. Un mutex por conexión serializa casos de uso y SQLite usa BEGIN IMMEDIATE y sus restricciones. Es un servicio de un proceso; no se afirma resolver carreras entre varias réplicas.
5. **Prioridad y obligaciones.** Se aplica DL-50 para que cuota agotada y denegaciones obligatorias dominen concesiones condicionales. Una cuota positiva insuficiente conserva QUOTA_CAP aunque haya HARD_DEADLINE, en lugar de ocultar el cupo por la primera restricción. La autoridad se deriva de las obligaciones. Esto es una resolución local de la contradicción ya registrada entre tabla y FR-8, no una aprobación humana de la planeación; requiere reconciliación documental formal posterior.
6. **Identidad y publicación.** Se adopta HTTP 401 para sesión ausente y 400 para `derived_from` inválido, que no tenían estado fijado. Publicar usa INSTRUCTOR+LAB_OPERATOR, cuerpo vacío y 201 con manifest. La publicación congela una nueva secuencia del mismo registro de esta compilación; no es un editor de reglas. Al arrancar se rechaza una base cuyo hash de reglas no corresponde a la compilación, en lugar de servir reglas distintas para una versión vieja.
7. **Congelaciones.** Preview HMAC-SHA256 con secreto configurable, verificación constante y consumo único. La codificación conserva el seam de fixtures previo. Los conjuntos de alcance se ordenan y deduplican. Se deja rastro draft_id en el detalle de auditoría para omitir borradores activados de la lista. El conteo se basa en el snapshot simulado de trabajos; la fixture por defecto está vacía y el servicio no inicia ni detiene GPU.
8. **Almacenamiento y eventos.** Migración inicial SQLite copiada del contrato sin columnas adicionales. Outbox durable, sin integración con broker ni entrega externa. No se almacena el pedido completo porque el esquema acordado no lo contempla; replay de respuesta sí, reevaluación autónoma a partir de insumos históricos completos no. Se requiere una migración diseñada para ese requisito de Impl-2.
9. **Ceremonia y revisión.** Se registran contexto, inspección, desglose, código+pruebas, verificación y revisión por historia. No se invocó un agente Amelia ni un comando `bmad-build`: esos ejecutores no están instalados en esta copia. El registro es una ejecución local de Codex del ciclo descrito en el PDF y una autorrevisión, no una revisión humana independiente. Las historias del anexo quedan ready-for-review.
