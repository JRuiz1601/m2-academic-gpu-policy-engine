## 1. Design Paradigm

**A pure decision function wrapped in a thin, honest shell.**

The module is one pure function — `evaluate(request, facts, policy_version) → Decision` — surrounded by exactly four responsibilities: fetch facts through typed ports, hand the result to a durable outbox, render it, and let other components act on it. Everything that could have gone *inside* the function was pushed out to a component that is better at it and worse at it in exactly the ways we want: the fact fetchers can be slow, the renderers can be pretty, the outbox can be durable. None of them is allowed to change the answer.

The organising rule: **the policy core decides, the shell explains, and nobody else has a vote.** A module that also writes quota, also kills jobs, and also reads the cluster is three modules sharing a trench coat, and none of the three can be tested without the other two.

### 1.1 What this module owns, stated as a closed list

| Owned (this module is the only writer) | Read-only | Explicitly not owned |
|---|---|---|
| `FreezeState` — the freeze aggregate, its draft records, and its preview runs | 8 typed fact ports (§2.1.1) | The historical query surface and long-term retention of the decision journal (the Audit Ledger, SPINE rule 1/4/8, `prd.md` NG-10); this module owns and writes, append-only, the per-decision records `DECISION`, `TRACE_ENTRY`, `CONSTRAINT` and `FACT_SNAPSHOT`, which the Ledger consumes through the outbox *(P1-ARCH-AMEND D5)* |
| `PolicyVersion` — the frozen rule set, its hash, its publication record | the platform event bus (publish + consume) | Quota balances (M8) |
| `DecisionOutbox` — the delivery record and the idempotency map (§4.2) | the cluster's projections, through M3 | Cluster state and job lifecycle (the Bridge, SPINE rule 2/5/7) |
| | | Reservation and timetable records (M4) |
| | | Allocation, preemption, and enforcement (Gateway, M9, Reservation Coordinator) |

Revision 1 of this document claimed ownership of the journal **and** built a query surface for it. That is a scope violation against `prd.md` NG-10 and SPINE rules 1, 4, and 8, and finding **ARCH-2** is its correction. The consequence is worth stating because it changes the architecture rather than the wording: this module has **no** `GET /policy/decisions` route, so it has no index design to get wrong, no result-ordering guarantee to make, and no retention policy to argue about. It emits `policy.decision.v1`; the Ledger persists and serves history.

**Reading the arrows.** Solid = synchronous call. Dotted (`-.->`) = read. Thick (`==>`) = a message or an obligation handed to a component this module does not control.

**No arrow from M2 writes to M8, M4, the cluster, or the Ledger.** That absence is the architecture, and it is now true of the diagram as well as the prose — the previous revision drew a `valid_until re-check` arrow into the cluster and then stated in its caption that no such arrow existed.

Two arrows that look like writes are not, and the distinction is named because it is the one an implementer will get wrong:

- `OUTBOX ==> BUS` is a publish. The module's only effect on the journal is a message.
- `SHELL ==> M9` is an **obligation**: *this decision's authority lapses at this instant, and the M9 Night Scheduler will act on it.* It is a command to enforce, never a request for permission, and the module never asks whether M9 complied before answering a caller.

### 2.1.1 The port register — one row per port, referenced by every other table

This table is the single definition of what a "fact port" is. `M2-AD-4` classifies by **port**, with **two** bounds each, exactly as `prd.md` FR-10 specifies. Revision 1 classified by *rule family name* and carried a single bound, which is the scheme `prd.md` NFR-13 was written to delete. **Ten register rows, nine named entries in FR-10:** the `Identity/Access` entry there is rows 1 and 2 here, and `Bridge` in FR-10 is now rows 6 and 7. The reconciliation test reads *this* table and asserts the FR-10 grouping, so a future port cannot be added to one document and forgotten in the other.

| # | Port | Owner | Method | On error | Admission tolerance | Display tolerance |
|---|---|---|---|---|---|---|
| 1 | `identity.v1.Identity` | M1 | `Resolve(session_token) → {actor_id, actor_kind, system_role}` | `FAIL_CLOSED` | 0 s | 0 s |
| 2 | `access.v1.Access` | M1 | `GetActor(actor_id) → {role_tier, subject_ids[], clearance}` | `FAIL_CLOSED` | 0 s | 0 s |

**Why `fleet` is two ports and not one.** Revision 2 registered a single `fleet.v1.Bridge`, which made one tolerance serve two unrelated facts. The **class table** — what hardware physically exists and how much VRAM each class has — is the sole evidence for `R-TIER-01`'s `DENY(HARDWARE_UNSATISFIABLE)`, and a `DENY` whose only fact is admissible from a 60-second-old cache is a refusal that can be wrong, which is worse than a refusal that is unavailable. The **availability counters** are contention state, and answering from a 60-second-old copy is exactly right: the requester is being told to wait, and the wait estimate is re-fetched. `prd.md` NFR-13's clause *"every rule's fail mode is derived from its declared inputs"* is what forces the split, because `R-TIER-01` and `R-CONTEND-01` read different fields of what was one port. Finding EDGE-6.

**Every adapter returns a typed result, and a negative answer is not a fault.** A port call has four outcomes, not two, and collapsing the middle two is how a mistyped identifier becomes a system fault and a truncated body becomes a silent pass:

| Shape | Example | Classification |
|---|---|---|
| `ok(value)` | the fact is present | a fact |
| `notFound` | HTTP 404 — the actor, model, or reservation does not exist | a **MISSING** fact: `R-VALID-01` decides it, cited and journalled. Never `R-DEP-01`, never served from cache — a deleted model must not resolve to a stale entry carrying a revoked licence |
| transport error / over-age value | a timeout, a 5xx, a cached copy older than the admission tolerance | classified by the register: `FAIL_CLOSED` or `ADMISSION_STALE_TOLERANT` |
| `ok(malformed)` | HTTP 200 whose body does not satisfy the port's schema | **promoted to a transport error** and classified by the register. A rule predicate is a total function over the fact type, so a field that is absent must not reach it: `undefined − undefined` is `NaN`, `NaN ≤ 0` is false, and a truncated fleet payload therefore fails **open** on a 24-machine reservation. `test/arch/ad4-payload-schema.test.ts` and a totality property test close both halves. Finding EDGE-5. |

**The clock carries a quality, not just an instant.** `FAIL_CLOSED(0)` on a `campus.clock` that reports only an instant is not a control: an age computed as `fetched_at − reported_at` is **negative** when the campus NTP steps backwards, and `negative > 0` is false, so the one port with a zero tolerance passes its own test — and a two-second backward step at 08:13 walks around a freeze that began at 08:00, with a clean, fully attributed trace. A reading is rejected, and therefore a port error under the register, when `stratum ≥ 15`, when `leap_indicator ≠ 0`, when the reported age is negative, or when the instant is earlier than the previous reading this process accepted. `/ready` asserts `stratum ≤ 4`. Findings EDGE-8, EDGE-27.

Two entries are **not ports** and are listed here so that no other table has to guess:

| Store | Nature | Failure behaviour |
|---|---|---|
| `FreezeState` | an in-process table in the module's own store | a read failure is `503` with a problem-details body and **no** `Decision` is recorded — a decision produced without knowing whether a freeze is active is not a decision |
| the module's database connection | the substrate every owned aggregate sits on | `FAIL_CLOSED` via `R-DEP-01` with `cause = DEPENDENCY_UNAVAILABLE` |

`DISPLAY_ONLY` is the third class and it is not a weakening of the first two: a fact used only for a non-binding display field (`queue_estimate_ref`'s display string) may be missing, and the decision is unchanged. A fact that can change `outcome`, `admission`, `valid_until`, or any constraint is `FAIL_CLOSED` or `ADMISSION_STALE_TOLERANT`, and those two bounds are stated separately because "how old may this be before I still admit you" and "how old may this be before I stop showing it to you" are different questions. Revision 1 answered both with one number, which is why `prd.md` finding PRD-3 (Critical) existed.

**The admission tolerance is enforced, not declared.** An `ADMISSION_STALE_TOLERANT(max_age)` port whose only available value has `age > max_age` escalates: it is treated as a `FAIL_CLOSED` failure, producing `DENY` with `R-DEP-01`, `cause = <PORT>_STALE_EXPIRED`, and `retry_after_ms = 2000`. Without this clause the tolerance is decorative in the only branch that uses it — the branch fires for *any* cached value, so a 60-second fleet tolerance and a 24-hour catalogue tolerance are the same number in practice, and an implementation that honours the tolerance instead refuses every request while a recovering dependency's cache ages past 60 s, which is a self-inflicted outage of the safest kind. The test matrix carries all four boundaries: `max_age − 1 ms`, `= max_age`, `max_age + 1 ms`, and `max_age` with no cache at all. Finding EDGE-27.

**The cap aborts; it does not stop waiting.** When a port exceeds `FACT_TIMEOUT_MS`, the cancellation signal is propagated to that port's client and the call is counted in the `/health` metrics as `fact_aborts_total`. Letting six calls per evaluation run to completion behind a deadline would leave up to 600 orphaned upstream calls inside a 100-concurrent p99 window, converting the module's latency problem into the platform's.

## 3. Core Component Interaction — the non-trivial algorithm

The interesting part of this module is the resolution order, not the request handling. This diagram **is** the algorithm, and it is the specification an implementer will follow, so it carries no arrow that contradicts an invariant. Revision 1's diagram placed the journal append before the response, drew the core reading the registry mid-walk, had the core and the shell disagreeing about who computed `valid_until`, and left a failure branch that fell through into a second full evaluation.

```mermaid
sequenceDiagram
    autonumber
    participant C as Client (via Gateway)
    participant S as Decision Shell
    participant R as Rule Registry (resolved in-memory, frozen)
    participant F as Fact Ports 1-9 (parallel, 40 ms cap each)
    participant P as Policy Core (pure)
    participant X as Explanation Renderer
    participant O as Decision Outbox
    participant B as Event Bus → Audit Ledger
    participant D as M9 Night Scheduler (obligation)

    C->>S: POST /policy/decisions {request} + Idempotency-Key
    S->>S: wire-shape parse (transport only — NOT a decision)
    S->>O: lookup Idempotency-Key
    alt key already evaluated
        O-->>S: the existing decision
        S-->>C: 200 {Decision} (replay, no re-evaluation)
    else new key
        S->>S: read campus.clock FIRST — one instant, becomes evaluated_at
        par resolve + fetch, in parallel, 40 ms cap each
            S->>R: resolve(policy_version) → frozen rule set + hash
            S->>F: identity, access, catalog, timetable, reservation,<br/>node class table, availability, quota, queue
        end
        S->>S: assemble immutable DecisionContext
        S->>P: evaluate(request, facts, policy_version)  ← the rule set is an argument
        P->>P: build boundary set B (§6.3 of the PRD)
        loop rules in ascending precedence −1 … 17, strict total order
            P->>P: evaluate predicate against the context
            alt rule fires with a terminal outcome
                P->>P: primary_rule_id = rule; every rule below → NOT_EVALUATED; break
            else predicate false
                P->>P: trace += (rule, NO_MATCH, evidence)
            else a required port is unavailable or past its admission bound
                P->>P: trace += (R-DEP-01, MATCH) → DENY(DEPENDENCY_UNAVAILABLE); break
            end
        end
        P->>P: bound = MIN(own completion, min(B) − PROTECTION_GRACE)  ← computed BEFORE the walk
        P->>P: past-bound guard; single deadline; single constraint group
        P-->>S: Decision (deterministic, no I/O, no clock)
        S->>X: render(Decision, template)
        X-->>S: rationale + citations + next_actions (no model, no clock, no network)
        Note over S,X: a template render failure NEVER suppresses the decision —<br/>the shell falls back to a field-derived rationale, still returns 200,<br/>and raises an alarm. A computed decision may not vanish into a 500.
        S-->>C: 200 {Decision}                        ← the answer is returned FIRST
        S->>O: append(outbox row, decision_id, payload)   ← ONE transaction: decision, trace, constraints, snapshot
        O==>>B: policy.decision.v1 (at-least-once, never blocks the response)
        S==>D: obligation: must_checkpoint_by (= valid_until)
        Note over S,O: a bus outage buffers 10 000 events, raises journal_lag,<br/>and alarms past 60 s. It never fails a request (NP-10).
    end
    else the shell or a port failed before any Decision existed
        S-->>C: 5xx problem-details — NOT a Decision, no outcome field
        S->>O: append policy.decision.failed.v1 (DECISION_OUTBOX row with failure_id set)
        Note over S,O: the journal is never short a row for a request the shell accepted
    end
```

### 3.1 The core rule, in one paragraph

> Walk the 19 rules in ascending precedence. The first rule whose predicate is true **and** which declares a terminal outcome ends the walk, becomes `primary_rule_id`, and every rule below it is recorded `NOT_EVALUATED` — never `NO_MATCH`. If the walk completes with nothing fired, `R-ALLOW-01` at precedence 17 admits the request and is named as the primary rule.

The `NOT_EVALUATED` / `NO_MATCH` distinction is the best single idea in this module and it is unchanged from revision 1. A trace that claims a request was tested against rules that never ran is a fabricated audit record, and it is the failure that lets a shadowed rule (see `M2-AD-2`'s subsumption clause) go unnoticed for a whole release cycle.

The fall-through changed, and the change is recorded because revision 1's version was a defensible idea aimed one level too low. Revision 1 said: *if no rule fires, `DENY` with `R-NO-RULE-MATCH`, because an unattributable decision is unauditable.* The premise is right and the mechanism defeats it: `R-NO-RULE-MATCH` is not in the rule registry, so the `DENY` it produces has a `primary_rule_id` outside the registry, no citation, and no template — it is the unattributable decision the invariant was written to prevent, wearing the costume of the thing preventing it. The idea belongs at **boot and monitoring** time, not at request time, and that is where it now lives:

- `test/arch/ad2-coverage.test.ts` asserts the shipped catalogue is total over its declared input space, so a new `workload_kind` or a new node class cannot be added without a rule that covers it.
- `test/arch/ad2-subsumption.test.ts` asserts no rule's predicate is a strict subset of another's (`prd.md` AG-9), so a shadowed rule fails the build rather than the semester.
- `R-ALLOW-01`'s firing rate is a monitored metric with a stated ceiling, because a rising default-admission rate is the signal that the catalogue has a hole — and a named, cited, journalled `ALLOW` is a **better** report of that hole than a `DENY` nobody can act on.

Rejected alternatives for the fall-through are recorded in `ai-log/decision-log.md` as **L-10**.

### 3.1 The walk, and the two orderings that carry a consequence

The core evaluates the 19 rows of `prd.md` §6.2 in ascending precedence and stops at the first terminal outcome. Two orderings in that list are **not** free, and both were arrived at by following a correction through to its consequence rather than by assuming the consequence went away.

**`R-FRZ-02` at 2 is terminal for any request whose `exam_binding` matches.** It therefore pre-empts `R-AUTH-01` at 8 and `R-AUTH-02` at 7, and revision 2's claim that *an allowance does not bypass authorisation* became false the moment the allowance moved above the clearance rules (decision-log **L-7**). The guarantee is restored at precedence −1, where the binding is validated: `R-VALID-01` requires the actor to hold an entitlement to the reservation's `subject_id` and answers `DENY(NOT_AUTHORIZED)` when it does not. A binding that does not survive that check is **no binding at all**, which makes the rest of the catalogue uniform — every rule that tests for an exemption tests for a *validated* one, and there is exactly one definition of validated. The declined alternative was a `R-FRZ-03` above the allowance, on the grounds that a freeze's job is to stop compute, not to grant it: a freeze carrying its own opinion about authorisation would be a second authorisation system with a different rule set and its own drift. Recorded as **L-12**.

**`R-DEP-01` at 0 precedes `R-FRZ-01` at 1.** A freeze read is not a remote port, so `R-DEP-01` at position 0 can only reach the request when some *other* port has failed, and `DEPENDENCY_UNAVAILABLE` with `retry_after_ms = 2000` is then the more actionable message — it names what to wait for. The cost is that a requester under an active freeze may be told to retry rather than that the fleet is frozen, and the mitigation is structural: the freeze console renders its own always-visible banner from the same `FREEZE` table, so the freeze state is communicated by the surface that owns it rather than by whichever denial happened to be produced first. A module that communicated the freeze *only* through denials would be telling the requester about the freeze at the moment they could least use the information.

## 4. Data Model

Revision 1's diagram was not implementable as drawn: `TRACE_ENTRY.seq` was a bare primary key (so the *second* request in the process's lifetime violated it), seven query filters had no columns to filter on, `derived_from` permitted an unbounded chain, nine normative fields of `Decision` were missing, the constraint enum was open with `...` in it, and there was no `POLICY_DOCUMENT` store for `M2-AD-6` to validate citations against. ### 4.2 Decisions that are architectural, not cosmetic

- **`TRACE_ENTRY` is keyed `(decision_id, seq)`.** The ordinal is per-decision. A bare `seq` primary key makes the second request in the process's lifetime fail to record — the review found this by reading the diagram, and it is the kind of defect that only appears after the first happy-path demo.
- **`evaluated_at` has `CHECK (evaluated_at = FACT_SNAPSHOT.campus_now)`** (a cross-table equality that no `CHECK` can express; both SQL files enforce it with the insert trigger `decision_evaluated_at_matches_snapshot` — TF-13). `prd.md` NFR-3 makes that identity definitional, not incidental. Two types for one value (a `timestamptz` column and a string with an offset) is a defect on its own, and it is the defect that made `M2-AD-8`'s determinism test unfalsifiable in revision 1.
- **`decision_id` is `uuid7`, not `uuid4`.** The tiebreaker for decisions sharing a millisecond has to be monotonic, or "chronological" ordering is decided by a random number that no auditor can reproduce and no reader of the journal can narrate. This costs 7 bytes of type discipline and removes a class of unexplainable output.
- **`depth CHECK (depth <= 1)` with `parent_kind`.** Revision 1's `derived_from` permitted A→B→C→D and then defined no term for "top-level", so the test that was supposed to prove a derived decision creates no second entry asserted an undefined noun. Bounded depth plus an explicit parent kind is the fix, and `test/arch/ad8-derived.test.ts` now has a predicate to assert.
- **`FACT_SNAPSHOT` is a typed projection, not a passthrough.** Revision 1 stored `jsonb actor` — a copy of whatever the Access Manager returned. The Access Manager owns an academic directory; a name and an institutional address are its normal payload. Storing the response as-is violates the "actor ids only" rule **at write time**, before any scrubber can report it, and puts the raw payload on an authenticated read path. A projection to the seven fields the rules actually read makes the rule a schema property instead of a scrubber's discovery.
- **`OBLIGATION_OBSERVATION` exists because a UX state needed a source.** `ux/C-UX-Scenarios/scenario-3.md` §3.7 specifies a deadline-violation state that distinguishes *the enforcing component did not signal within 60 s* from *the bridge confirmed the job is still running*. Those are two different faults with two different owners, and neither had an event, a port, or a place to be written down. `job.lifecycle.v1` is a **permitted read** under SPINE rule 5, and `OBLIGATION_ACK` is an outbound publish. Finding ARCH-22.
- **`POLICY_VERSION.content_hash` covers more than the rules.** It covers the rule set, the versioned constants (`NIGHT_WINDOW`, `PROTECTION_GRACE`, `NEAR_BOUNDARY_DISPLAY_HORIZON`), `CAMPUS_TZ`, and `engine_version`. Revision 1 hard-coded a 300-second grace outside the hash while claiming that last week's denial was reproducible against the rule that produced it — true for capability decisions, false for **every** temporal decision, which is most of them. Finding ARCH-26.
- **Freeze scope is a predicate, not a vibe.** `in_scope(freeze, request) := (scope = 'ALL') ∨ (scope = 'SUBJECT' ∧ request.subject_id ∈ subject_ids) ∨ (scope = 'NODE_CLASS' ∧ request.node_class_id ∈ node_class_ids)` — a **disjunction**, and each arm implies the other array is empty, enforced by the `CHECK`s above. The reading that was left undefined changes the outcome by a total denial of service: under an intersection a freeze covers *nothing* while the console renders an active-freeze banner and the audit records an activation, and under a union it denies subjects the freeze authority did not select. `allowances = null` is not an alternative spelling of `[]`; the `CHECK` exists because `allowances.some(...)` throws on it and because a corrupted object makes the exemption test truthy inside an examination freeze. Finding EDGE-11.
- **`FREEZE.state` is stored intent; `EXPIRED` is computed on read and is stored only by the closing step of `activateFreeze` (TF-5).** `ACTIVE` means *activated and not lifted*; liveness is `state ∉ {DRAFT, LIFTED, EXPIRED} ∧ starts_at ≤ t ∧ t < ends_at`, evaluated inside the rule predicate from the clock on every evaluation. A row left unswept past its `ends_at` therefore denies nothing, and the rule text is the mechanism rather than a reconciliation job. `activateFreeze` closes, in its own transaction and before inserting, every `ACTIVE` freeze of the same normalised scope whose `ends_at <= campus_now`, by writing `state = 'EXPIRED'`; that closing step writes no event (TF-5). `/ready` runs the expiry reconciliation as a **non-blocking** reconciliation and reports the count; it is never a gate, because a gate would refuse traffic to repair a table that is already refusing nothing.
- **The append is one transaction.** `(DECISION, TRACE_ENTRY[], CONSTRAINT[], SUPPRESSED_RULE[], DECISION_CITATION[], FACT_SNAPSHOT)` are written together, so the `1:1` in the diagram holds and a crash cannot leave a `DENY` whose evidence was never stored. Eviction is bounded by `retention(window) = max(decision_retention, snapshot_retention)` and flips `snapshot_retained`, and a read of an evicted snapshot is `410 SNAPSHOT_EVICTED` — distinct from `404` (unknown id) and distinct from a fault, because "this refusal can no longer be reproduced" is a different statement from "no such decision" and an audit surface that conflates them is lying about one of them. Finding EDGE-20.
- **The record names two principals.** `originating_actor_id` is the human the request is *for*; `submitted_by` says whether a person or the engine pressed the button. An auto-proposed alternative submitted on the requester's behalf is filtered to her journal by `originating_actor_id` and is simultaneously flagged `submitted_by = SYSTEM` — without both columns the row is either invisible to the person it concerns or indistinguishable from her own submission, and `prd.md` NFR-5's ids-only discipline gives an auditor no way to see that no human touched it. Finding EDGE-19.
- **No IEEE-754 double crosses the journal boundary.** Every numeric field is an integer with the unit in the name (`earliest_wait_seconds`, `denied_count`, `reclaimed_gpu_seconds`) or a fixed-point decimal with a declared scale. `NFR-3`'s byte-identical guarantee is measured through a `jsonb` column, and `jsonb` renders numbers by its own precision and scale rules rather than by IEEE-754 round-trip rules, so one float turns a SQLite→PostgreSQL adapter swap into an intermittent determinism failure that looks like an engine bug. `prd.md` FR-8 already applies this discipline to the quota balance; the whole `Decision` contract now applies it. Finding EDGE-28.

- **A clearance is an object, not two nullable integers.** `Clearance { max_gpu_count, max_vram_gb, unrestricted: bool }`, with `unrestricted` **explicit**: a null cap and an infinite cap are different facts, and over two nullable scalars they are indistinguishable, so `R-TIER-02` refuses a Night Training Daemon for physical infeasibility it did not cause on one reading and admits it to an auto-substituted variant on the other. The daemon's narrowed rule set is data, not prose: `prd.md` `R-SYS-01` at precedence 11 plus the `actor_kind = HUMAN` guards on the human temporal rules, published in the registry and recorded in the trace as `NOT_EVALUATED` with `reason = ACTOR_KIND_FILTER` — never a silent skip, because a rule that quietly does not run is the same defect as a rule that quietly cannot fire. Finding EDGE-12.
- **Canonical ordering** is the table below, transcribed from `prd.md` §6.5. It is here because `NFR-3` is a property of the serialised record, and a property of a record cannot be asserted by a document that does not state the record's order.

| Collection | Order | Reason |
|---|---|---|
| `subject_ids[]`, `allowances[]`, `node_class_ids[]`, `citations[]` | lexicographic | no intrinsic order; any other choice is a map iteration |
| `node_classes[]` | `class_id` | lookup key |
| `protected_windows[]` | `(starts_at, window_id)` | the boundary set `B` is derived from it, so a re-order would change `b*` on a tie |
| `freeze_states[]` | `(starts_at, freeze_id)` | same |
| `trace[]` | `(precedence, rule_id)` | the walk order, which is the audit order |
| `suppressed[]` | `precedence` | same |
| `constraints[]` | `(kind, deadline, value)` | |
| `next_actions[]` | `action_id` | the primary action carries a sort key so it sorts first |
| `boundary set B` | ascending instant, then source `window_id`/`freeze_id` | `b*` must be unique |

## 5. API and Event Contracts

### 5.1 External API — 13 routes, the module's entire public surface

Every route requires an authenticated caller **except `GET /health` and `GET /ready`, which need no authentication** — 11 of the 13 routes authenticate (P1-ARCH-AMEND D4). **All four freeze-mutating routes** — create draft, preview, activate, lift — plus `GET /policy/freezes` and `GET /policy/freezes/{id}` additionally require `role_tier ≥ INSTRUCTOR` with a `LAB_OPERATOR` scope, and activation re-reads that tier **fresh at activation time**, never from the preview's snapshot. A `preview_token` is a freshness token, not an authorisation token: it expires in 60 seconds and says nothing about who may freeze the fleet, so treating it as the gate leaves the module's one irreversible action behind a wall of 33 GPUs one authenticated student session away. **The session actor is authoritative; a `Request.actor_ref` that differs from it is `R-VALID-01` at precedence −1** — a client cannot assert who it is. Findings ARCH-30, EDGE-7.

**Four contract decisions that revision 1 got wrong, and each one is a defect class worth naming.**

**A `DENY` is `200`, on both routes.** `DENY(WINDOW_PROTECTED)` is a *successful evaluation that returned an answer*. Revision 1 returned `403` with a `Decision` in the body, which is self-refuting: if the body is a `Decision`, the operation succeeded. `prd.md` FR-16 and `ux/EXPERIENCE.md` law 2 ("a refusal is a result, not an error") both forbid it, and the ban is on the *string* `403` appearing in a rendered card, so the lint would have failed the build. `4xx` is reserved for a body that does not parse; `5xx` is reserved for the engine being unable to decide. The preview route returns the same codes for the same decision, because the console's CLI and GUI read the same payload and a client that learns the code from one route must not be contradicted by the other. Finding ARCH-6(a), (b).

**`Idempotency-Key` is required on `POST /policy/decisions` and optional on `POST /policy/decisions/preview` (that route is not journalled).** `ux/EXPERIENCE.md`'s `E-SYSTEM` state mandates three automatic retries with a visible countdown, and the designed retry flow is therefore `503` → retry ×3 → **three** `POST /policy/decisions` calls. Without a key that is three decisions, three trace sets, and three `policy.decision.v1` events for one attempt at one instant — in a module whose justification is that an unattributable decision is unauditable. `IDEMPOTENCY_KEY` holds the key→`decision_id` map, unique per `(actor_id, key)`, with the request body hash stored; a replay within the 24-hour window returns the original `Decision` without re-evaluating, and a replay with a different body is `409`. The client must supply the key on `POST /policy/decisions`; there are no server-derived keys (P1-ARCH-AMEND D2). `IDEMPOTENCY_KEY` rows are never deleted and stay unique per `(actor_id, key)`; a call whose key row exists with `replay_window_expires_at <= now` is refused with `409 IDEMPOTENCY_KEY_EXPIRED` and the client must send a new key (K3). A second call with the same `(actor_id, key)` that arrives while the first is still in its transaction waits on the unique constraint, then returns the stored `Decision` (same body hash) or `IDEMPOTENCY_BODY_MISMATCH` `409` (different body) (K3). Finding ARCH-6(c), ARCH-30.

**`preview_token` is server-issued over server state.** Revision 1 defined it as a hash of the draft freeze, which proves only *the caller knows the draft* — a value the caller already holds, and which it can compute with `sha256sum` without ever calling the preview route. The requirement is that activation is blocked when the preview was not computed, so the artefact must be evidence that the server ran the computation. The preview route therefore **persists** a `PreviewRun` and returns a token that carries the `preview_run_id` and is signed with `HMAC(server_secret, draft_id ‖ content_hash ‖ actor_id ‖ issued_at)` (TF-7). Activation recomputes the HMAC, locates the `PreviewRun` by `preview_run_id`, then checks in this order: signature, actor (`TOKEN_ACTOR_MISMATCH`), expiry, consumption, stale draft hash; two live previews of one draft are therefore unambiguous. Now `test/scenario/sa-5.test.ts` — "activation with the preview call stubbed to fail is blocked" — is falsifiable, and "a caller using `curl` cannot skip the preview either" is true, because `curl` cannot forge an HMAC over a row the server never wrote. Re-previewing refreshes the token, so the keyboard path in UX-4 (scope → window → preview → confirm → modal → reason → confirm) survives an interruption. Finding ARCH-7.

**The freeze preview returns only what this module can compute.** Revision 1 returned `running_count` and `reclaimed_gpu_hours` and marked a failure as activation-blocking. Those two values are job-lifecycle and cluster-runtime state; this module has no port for either, `prd.md` `R-CONTEND-01` states outright that the engine never computes a duration, and `M2-AD-5` forbids the cluster client that would supply them. The failure mode of the design as written was **"Dr. Reed cannot protect the exam room"** — the preview is most likely to fail in exactly the incident it exists for, and the block condition makes that the worst possible outcome. The response is now the three values `ux/EXPERIENCE.md` UX-4's loading state actually names as stat tiles — `denied_count` (*requests denied*), `survivors[]` (*nodes affected*), `next_protected_window` — all three derivable from facts the module already holds, with `runtime_snapshot: UNAVAILABLE` when a non-binding enrichment is missing. Blocking activation on a `503` from the preview call is retained, because "look before you act" is the requirement; blocking it on a fact the module cannot obtain is not. Finding ARCH-18.

**Two activations of one scope are resolved by the database, not by a prior read.** The `409 duplicate active freeze` in the table above is a **partial unique index** on the normalised scope key, taken `WHERE state = 'ACTIVE'`, and activation is a compare-and-swap on the freeze store's version. A read-then-write check is what a double-tap on a 44-pixel target under time pressure defeats: two transactions both read *none*, both insert, both commit, both publish `policy.freeze.activated.v1`, and both apply — after which every `R-FRZ-01` decision must choose which `freeze_id` to cite, and lifting one leaves the other active while the console says no freeze is in force. `N = 8` simultaneous activations of one scope produce exactly one `201` and seven `409`s. The upstream spine requires precisely this shape for reservation mutations (optimistic version check, not a global lock), and the freeze store is a new aggregate following that pattern. Finding EDGE-17.

**The token is single-use, actor-bound, and valid *at* 60 seconds.** `consumed_at` is written in the same transaction as the activation, so a second presentation is `409 TOKEN_CONSUMED`; the token is valid while `now <= issued_at + 60 s` and expired when `now > issued_at + 60 s` (K5), so the boundary instant is inside the window and the console's recovery for `PREVIEW_EXPIRED` is a one-tap recompute; and the token's `actor_id` is checked, so one freeze authority's preview cannot be spent by another. A replayable token inside its own validity window is not a precondition. Finding EDGE-31.

**The clock override exists, on one route, behind two gates, and in the record.** `ux/EXPERIENCE.md` law 5 requires that the named person debugging a boundary defect be able to set campus time, `prd.md` FR-14 requires every console action to be achievable through documented API calls, and the four evaluations in `ux/C-UX-Scenarios/scenario-3.md` are performed with an override — so the affordance is mandatory and the module had no way to carry it. Adding it to `POST /policy/decisions` would hand every `STUDENT` a walk around `R-NIGHT-01` and `R-LAB-01` and would write a forged `evaluated_at` into the journal. It is therefore a **query parameter on the non-journalling preview route only**, gated on `role_tier ≥ INSTRUCTOR` and on the deployment flag, and recorded in `FACT_SNAPSHOT` and the trace. `test/arch/ad1-offline.test.ts` additionally asserts the committing route ignores the parameter entirely, so the gate is not the parameter's name. Findings EDGE-10, ARCH-1.

### 5.3 The delivery publisher, since it is a component and not a footnote

`prd.md` NP-10 requires that a bus outage does not fail a request. That is a component with a buffer size, a retry policy, a lag metric, and an alarm, and revision 1 of this document mentioned none of it while drawing a synchronous append in front of the response — which is the same design NP-10 exists to prohibit.

| Property | Value | Why |
|---|---|---|
| Buffer | 10 000 events in memory, flushed in batches of 256 | bounded, and large enough to cover a 60 s bus outage at the observed request rate |
| Retry | exponential, 50 ms → 3 s, no cap | a bus outage is usually minutes, not seconds |
| On overflow | drop the **oldest** and raise `journal_overshoot` | the newest decisions are the ones being argued about |
| Lag metric | `journal_lag` = now − the first attempt (`OUTBOX_DELIVERY.attempted_at` of `attempt_no = 1`; the outbox row's `created_at` while no attempt exists: PROPOSED, human to confirm) of the oldest outbox row with no `OUTBOX_DELIVERY` row carrying a non-null `delivered_at` (P1-ARCH-AMEND D3). A computed query, not a stored column (TF-4) | one number answers "is the audit trail behind?" |
| Alarm | `journal_lag > 60 s` pages | 60 s is the same threshold UX-3's journal view uses to show a lag banner, so the console and the pager agree |
| Effect on a request | **none** | a decision that cannot be published is still returned, still held in the outbox, and still replayed on recovery |

## 6. Architectural Invariants (M2-AD-1 … M2-AD-9)

Each is stated in the mandated five-part structure. The banned-term list is `prd.md` FR-15's, by reference — this document keeps no list of its own, because two lists diverge. Each invariant names its proof, and §11 adds a third column stating **what fails if the invariant is broken**, because a verification plan whose rows are unfalsifiable is worse than none: it moves the risk from "untested" to "believed tested".

### M2-AD-1 — The policy core is a pure function of three arguments, and every decision is attributable to exactly one rule

- **Status:** `[ADOPTED — REVISED]`
- **Binds:** `policy/core` (rule evaluation, the precedence walk, boundary-set construction, constraint expansion), all 19 `R-*` rules, the `Decision` constructor.
- **Prevents:** two code paths producing different answers for the same request — a short-circuit path that reuses a partial fact set and a full path that re-reads — so that a request is admitted by one and refused by the other depending on which replica served it. Also prevents a decision with no attributable rule, which is unauditable and indistinguishable from a defect in production.
- **Rule:** `evaluate(request, facts, policy_version)` MUST be a pure function of its three arguments. The `policy_version` argument is the **already-resolved, frozen rule set**, not a version string to be looked up: the core performs no registry read. The `policy/core` package MUST import nothing outside the allow-list `prd.md` FR-13 declares, which denies `net`, `net/http`, `url`, `os`, `crypto/rand`, `time` outside the injected clock interface, `context` for outbound calls, and every database, gRPC, and Kubernetes client *(TypeScript equivalents, confirmed with the stack decision: `express`, `pg`, `better-sqlite3`, `node:http`, `node:net`, `node:crypto` for randomness, and the globals `Date.now`, `new Date()`, `Math.random`; same intent, no new rule)*. When the walk short-circuits, every rule below the terminal rule MUST be recorded `NOT_EVALUATED`; recording it `NO_MATCH` is a violation. The walk cannot end with nothing fired: `R-ALLOW-01` at precedence 17 is the last row and always produces a terminal outcome, so a `Decision` whose `primary_rule_id` is outside the registry is a constructor error. Two further clauses belong to this invariant because they are the same failure seen from two directions. **(a) Per-request isolation.** The shell MUST assemble each fact set into a per-request structure and MUST NOT memoise a port response across evaluations, nor key any cache on less than the full `(actor_id, subject_id, model_ref, node_class_id, campus_now)` tuple. A wrong-person fact is the highest-consequence defect available to this module and it is invisible: the core is pure, so it evaluates a mis-keyed actor without complaint, the rule ids and the trace are internally consistent, and the result is a fully attributed decision about the wrong person. **(b) An explanation failure never suppresses a decision.** A template render error MUST fall back to a field-derived rationale, MUST NOT turn a computed `Decision` into a fault, and MUST raise an alarm; the failure of a *presentation* step is not permitted to remove a *decision* from the journal.
- **Trade-off:** the core cannot read reference data, so every fact must be fetched by the shell and marshalled in — one allocation per evaluation, and no in-rule enrichment: a rule cannot itself ask the catalogue to discover a variant, so the shell must pre-resolve candidate variants into the fact set. The core also cannot be served as a standalone HTTP endpoint without a wrapper, which adds a component whose only job is to keep the core pure. A generated `Decision` may never be the product of a code path that skipped the walk.
- **Enforced by:** `test/arch/ad1-imports.test.ts` (the import allow-list, enforced against the **shipped** module graph, not a fixture) · `test/arch/ad1-offline.test.ts` (drive `evaluate()` with the fixtures directory made unreadable and no network reachable; and assert the committing route ignores `?evaluated_at_override`) · `test/arch/ad1-trace-complete.test.ts` (remove one rule from a fixture registry; assert the `NOT_EVALUATED` count drops by exactly one and `primary_rule_id` is unchanged) · `test/arch/ad1-isolation.test.ts` (interleave two actors' evaluations 10 000 times with per-port latency jitter; assert zero cross-contamination — the shell's analogue of a purity test) · `test/arch/ad1-render-fallback.test.ts` (a template that throws still yields `200` plus a journal row).

> **Why the gate mechanism changed.** Revision 1 proved purity with a **symbol-name scan** — "no reference to `Date.now`, `time.Now`, `new Date()` without arguments, `Math.random`". That is defeated by one line of aliasing, and the PRD had already named the defect: *"a symbol scan is defeated by a one-line alias."* The parenthetical "without arguments" made it worse, because it permitted `new Date(t)` and so permitted time arithmetic in the core, which is the thing the invariant exists to prevent. An **import allow-list** is a property of the module graph and survives renaming. Finding ARCH-19. Revision 1's second test also re-asserted a `NOT NULL` column — the type system, not the invariant — and never touched the `NOT_EVALUATED` clause, which is the part with content.

### M2-AD-2 — Precedence is a strict total order, declared in data, validated at boot, and free of subsumed rules

- **Status:** `[ADOPTED — REVISED]`
- **Binds:** the rule registry, the boot validator, all 19 rule definitions.
- **Prevents:** two rules sharing a precedence value, whose relative resolution then depends on iteration order — producing different decisions on different processes for identical input, which destroys NFR-3 in a way that **survives every functional test** because the tests all run in one process. Also prevents a rule that can never fire from shipping unnoticed, and a new rule silently shadowing an existing one.
- **Rule:** every rule MUST declare a unique integer `precedence` in `[−1, 1000]`. The range is **inclusive of −1** because two rules legitimately precede the numbered catalogue: `R-VALID-01` at −1 and `R-DEP-01` at 0. Revision 1's `[1, 1000]` would have refused to boot on the module's own registry. At startup the validator MUST exit non-zero if two rules share a precedence, any precedence is outside the range, any rule lacks a `citation_id` or a `rationale_template_id`, any `citation_id` does not resolve in the `POLICY_DOCUMENT` registry, any `DENY` cause is produced by no rule or by two, or any rule's declared predicate is a **strict subset** of another rule's, or any field declared in a fact type is read by **no** rule and by no named non-decision surface. That last clause is the registry validator generalised to the data model, and it exists because a field can be declared, cited in an acceptance criterion, and read by nothing: `prd.md` finding PRD-14 added `required_node_count` and recorded it as "retained and now read", and the validator is what established that no rule reads it — its only consumer is the freeze preview's `next_protected_window` tile, which is a non-decision surface and therefore a legitimate reader. A field with no consumer at all is a promise the engine does not keep. The validator runs against the **shipped** registry on every process start and in every deployment probe — not against a fixture. The walk MUST iterate ascending and break on the first rule that both matches and declares a terminal outcome.
- **Trade-off:** inserting a rule mid-order requires renumbering and re-reviewing every rule after it, which is deliberate friction. A mis-numbered rule takes the service down at boot rather than mis-deciding at 09:00 on exam day: the team bought correctness with a boot-time availability cost. The registry cannot express two rules that are co-equal in intent - it forces an arbitrary order, and that arbitrariness is resolved by human judgement, which `AG-9`'s subsumption test then checks for the specific case where the judgement produced a rule that can never fire.
- **Enforced by:** `test/arch/ad2-precedence.test.ts` (the validator rejects a duplicate, an out-of-range value including a legal −1, a missing citation, and an unresolved `doc_id` — four fixtures, four failures) · `test/arch/ad2-shipped-registry.test.ts` (the validator passes on the registry that ships, and the registry contains a rule at precedence −1) · `test/arch/ad2-subsumption.test.ts` (no rule's predicate is a strict subset of another's) · `test/arch/ad2-fact-coverage.test.ts` (every field declared in a fact type has at least one named consumer — a rule input or a named non-decision surface) · a startup assertion in `/ready`.

> **Why the subsumption clause exists.** `prd.md` finding PRD-12 identified `R-GRACE-01` as shadowed by `R-STRADDLE-01`. The repair the review recommended — narrow `R-GRACE-01`'s workload set so the two yield different outcomes — would have made `R-GRACE-01` a **strict subset** of `R-STRADDLE-01`: a second dead rule, created by the repair. That was found during cross-document reconciliation and recorded as PRD finding **RC-2**, and the three rules are now one. A dead rule is not a control, it is a comment with a citation, and the only reliable detector is a test that asks the question mechanically. Findings PRD-12, RC-2, AG-9.

### M2-AD-3 — Half-open intervals, one boundary set, one deadline, and no expired bound

- **Status:** `[ADOPTED — REVISED]`
- **Binds:** `R-FRZ-01`, `R-FRZ-02`, `R-LAB-01`, `R-LAB-02`, `R-NIGHT-01`, `R-BOUND-01`, the boundary-set builder, the constraint expander, the `Decision` constructor, `DECISION.valid_until`.
- **Prevents:** the module's headline failure — a job admitted under the overnight policy that keeps running into a protected morning class window, disrupting a class and destroying a student's night of work while the audit record shows the engine permitted it. Also prevents one-millisecond ambiguity at window edges, the wall-clock arithmetic error across a DST transition, a deadline later than the admission it belongs to, and an admission that expired before the shell finished computing it.
- **Rule:** the module uses **two** time representations, and which one applies is not a matter of taste.

  1. **Containment** tests — `campus_now ∈ [starts_at, ends_at)` for `R-FRZ-01`, `R-FRZ-02`, `R-LAB-01`, `R-LAB-02`, `R-NIGHT-01` — MUST be evaluated on **campus-local wall time** resolved through the configured IANA zone `CAMPUS_TZ`. A window whose `ends_at` is not after its `starts_at` is a validation failure.
  2. **Bounding** — the boundary set `B`, `b* = min{ b ∈ B : b > campus_now }`, and `bound = MIN(campus_now + expected_duration_min, b* − PROTECTION_GRACE)` — MUST be computed on **absolute instants**. Campus-local time is used only to render the resulting deadline. Under a spring-forward transition a `01:00–04:00` window is 2 elapsed hours, so a search for the earliest boundary in wall-clock labels yields a different `b*` than a search over instants, and therefore a different `must_checkpoint_by` — a job stopped an hour early or an hour late.

  `B` is built once per evaluation from exactly three sources: the start and end of every `ProtectedWindow` the actor is enrolled in whose `ends_at > campus_now`; the start of every future freeze; and the end of the **enclosing access window** — which `prd.md` §6.3 defines as `NIGHT_WINDOW`'s end at 06:00 when `campus_now ∈ NIGHT_WINDOW` and no freeze covers the request, and otherwise the active freeze's `ends_at`. A source with no applicable instance contributes **nothing** to `B` and its absence is not an error; if all three non-duration terms are absent then `valid_until = campus_now + expected_duration_min`, stated here so that two implementers do not build two policies from one document. Every element is treated identically — none is more important than another, and the only question is which is earliest. `PROTECTION_GRACE` is read from the pinned version's constants, never from a literal in the source.

  **One deadline, and it does not depend on which rule fired.** For every `ALLOW` and every `CONSTRAIN`, `valid_until = bound`, and `must_checkpoint_by = bound` whenever `bound < campus_now + expected_duration_min` — that is, whenever *any* applicable bound cuts the requested work short, **regardless of rule attribution**. The single-producer clause that once sat inside a rule's aftermath produced a hole at exactly one instant: a request whose `campus_now + expected_duration_min` **equals** `b* − PROTECTION_GRACE` satisfies a strict-crossing predicate, so no rule fires, no `HARD_DEADLINE` is emitted, `must_checkpoint_by` stays null — and `prd.md` §9.2 has the Gateway check `valid_until` *at launch*, which passes. The job then runs into the class the module exists to protect, and the audit shows a clean `ALLOW`. The deadline is a property of the boundary set, not of the winning rule. `MUST` never be later than `valid_until`, in any circumstance.

  A window already fully in the past MUST be excluded from `B` entirely. If `b* − PROTECTION_GRACE ≤ campus_now`, the engine MUST NOT emit a constraint with a past deadline; it MUST emit `ALLOW` with `valid_until = campus_now`, `admission = ADMITTED`, and a `WINDOW_SCOPE` constraint naming the boundary and stating that no time is granted inside it. A `CONSTRAIN` with an expired deadline is a contradiction, and a delegate asked to enforce one has no correct behaviour. The `Decision` constructor MUST reject any `ALLOW` or `CONSTRAIN` whose `valid_until` is null **or** whose `valid_until ≤ evaluated_at`.

  **The evaluation instant is read once, first.** The shell MUST read `campus.clock` before any other fact fetch, and that single instant is the `evaluated_at` of the resulting `Decision`; the duration of the fetch MUST NOT shift it. `FACT_SNAPSHOT` holds exactly one `campus_now`, and if it were read last, a request arriving at 08:59:59.900 with a 140 ms slowest port would be evaluated at 09:00:00.040 and denied by `R-LAB-01` instead of admitted under a bound — the same 1 ms boundary precision the module is specified for, and the same request with a different answer, decided by the order of the shell's own fan-out rather than by policy. `NFR-4`'s property test supplies `campus_now` directly and cannot see this, so a shell test injects the delay instead.

  **`NIGHT_WINDOW` is published as a resolved instant pair.** It is the only predicate in the module expressed in wall time rather than as a pair of instants, and that makes it the only one a tzdata release can silently redefine: `[22:00, 06:00)` names different instants before and after an offset change, with no version bump, no `changed_rule_ids` entry, and no diff for the console's *Compare versions* action to show. The rule data therefore carries `night_window_starts_at` and `night_window_ends_at` resolved for the evaluation day, and campus-local time is used only to render them. `FACT_SNAPSHOT` records `campus_tz`, `utc_offset_seconds_at_evaluated_at`, and `tzdata_version`, so the time base of a decision is part of the record rather than a property of whichever host replays it.
- **Trade-off:** every `ALLOW` now carries an expiry, so the Gateway and M9 must honour `valid_until` at launch rather than admitting on a decision they cached earlier — an added hop and a new failure mode for components this module does not control. The grace is a single value for all boundary types, so a protected session gives up 5 minutes of machine time even when the room is empty. A single erroneous schedule entry can pull a `valid_until` close to `campus_now`; the past-bound guard **detects and neutralises** this (admit for zero time with a visible reason) rather than tolerating it, which is the difference between a data-entry error and an impossible decision. A boundary set built from instants means the display layer has to do the wall-clock conversion, and a renderer that forgets produces a deadline in UTC labelled as campus-local — caught by `ad3-render.test.ts`.
- **Enforced by:** `test/arch/ad3-boundary.test.ts` (1 000 generated boundary instants × **6 enumerated boundary kinds** — `LAB` start, `LAB` end, `EXAM` start, `THESIS` start, freeze start, overnight-window end — with the expected value **computed independently of the engine**, and only two legitimate outcome flips permitted) · `test/arch/ad3-dst.test.ts` (both branches of a DST transition, in **both** directions, asserting the two representations disagree and the instant branch is the one used for bounding) · `test/arch/ad3-past-bound.test.ts` (the past window is excluded; the past-grace case yields a zero-length `ALLOW`; a `valid_until ≤ evaluated_at` is rejected by the constructor) · `test/arch/ad3-deadline-attribution.test.ts` (the exact-equality case `now + duration == b* − PROTECTION_GRACE` still emits `must_checkpoint_by`, and a rule whose own boundary list disagrees with `B` fails) · `test/arch/ad3-clock-order.test.ts` (a 140 ms delay injected into one port leaves the outcome identical to a 0 ms run) · `test/props/single-deadline.test.ts` (over 10 000 generated contexts, `must_checkpoint_by = valid_until` in 100 % of cases) · `test/scenario/sa-3.test.ts` (the annex's mandatory edge case).

> **Why two representations, stated once.** Revision 1 collapsed them: *"Every window test MUST be evaluated as `starts_at <= t < ends_at` with `t` resolved to campus-local time"* — a single sentence that also covers the `MIN(...)` in its own next clause, mandating wall-clock arithmetic for the computation that must not use it. Its technology justification then argued that IANA time-zone data is what makes the campus-local comparison correct, i.e. it justified the stack against the half of the rule that is not delicate. Findings ARCH-13, ARCH-14.

### M2-AD-4 — Every fact port is registered, and every port that can change an outcome has a stated admission tolerance

- **Status:** `[ADOPTED — REVISED]`
- **Binds:** the port register (§2.1.1), all 10 adapters, `R-DEP-01`, the `DecisionContext` builder, the `stale_facts[]` computation.
- **Prevents:** a degraded dependency silently converting a refusal into an admission. This is the highest-consequence failure in the module: during an exam freeze with the quota service unreachable, a fail-open engine admits 70 GB training jobs onto the 24 machines the exam room needs, forty minutes before the exam, with no error anywhere. It also prevents the opposite failure — a contention check that hard-fails and refuses work that would have run — and prevents a classification scheme whose completeness cannot be measured.
- **Rule:** every fact source MUST appear as a row in the §2.1.1 register with an owner, a method, and **two** tolerances: an *admission* tolerance, after which a stale fact is treated as a failure, and a *display* tolerance, after which a stale fact is reported and no longer used for anything. A "registered port" is a row in that register and nothing else. A port error or an admission-tolerance breach MUST produce `DENY` with `primary_rule_id = R-DEP-01`, `cause = DEPENDENCY_UNAVAILABLE`, `retry_after_ms = 2000`, and MUST be evaluated **inside** the walk as a row at precedence 0 — not as a branch around it, because a branch around the walk produces a second decision path, which is what `M2-AD-1` exists to prevent. An `ADMISSION_STALE_TOLERANT` value **older than its own tolerance** is one of these errors, not a fact: without that clause the tolerance is decorative in the only branch that uses it, because the branch fires for any cached value and a 60-second fleet tolerance and a 24-hour catalogue tolerance are the same number in practice.

**Every adapter returns one of four shapes, and two of them are not errors.** `ok(value)` is a fact. `notFound` is a **MISSING** fact and is decided by `R-VALID-01` as a cited, journalled `DENY` — `ACTOR_UNKNOWN` for an id the Access Manager does not know, `MODEL_NOT_FOUND` for a ref the Catalogue does not know — never `R-DEP-01`, because a mistyped identifier is a request defect and rendering it as a system fault sends the escalation to the wrong person; and never a cached copy, because a deleted model served from a 24-hour-old cache resolves to a revoked licence and a superseded VRAM figure. A malformed body behind an HTTP 200 is **promoted to a transport error**: a rule predicate is a total function over the fact type, and a missing field is the cheapest fail-open in the module, because `undefined − undefined` is `NaN`, `NaN ≤ 0` is false, and a truncated availability payload therefore answers "the fleet is not contended" on a 24-machine reservation. The shell MUST schema-validate every port payload before it enters the fact set, and a totality property test asserts that no predicate is reachable with a non-finite or absent input.

**A `DENY` is never evidenced by a fact this invariant declares admissible.** `R-TIER-01` is the sole evidence path for a hard physical-infeasibility `DENY`, so the class table it reads is `FAIL_CLOSED` at 0 s on its own port; the availability counters it does not read are `ADMISSION_STALE_TOLERANT` at 60 s. One tolerance for one port would have had to be either correct for a refusal or correct for a wait estimate, and it cannot be both. `prd.md` NFR-13's clause that each rule's fail mode is derived from its declared inputs is what forces the split, and `test/nfr/nfr-13.test.ts` fails if the two merge back.

**The clock's quality is part of its contract.** A `campus.clock` reading is rejected — and therefore a register error — when `stratum ≥ 15`, when `leap_indicator ≠ 0`, when the reported age is negative, or when the instant precedes the last reading this process accepted. An age-only check of `FAIL_CLOSED(0)` passes a **backward** step, because `negative > 0` is false, and a two-second backward step at 08:13 walks around a freeze that began at 08:00 while producing a clean, fully attributed trace. `/ready` asserts `stratum ≤ 4` in addition to reachability.

A fact past its **display** tolerance but within its admission tolerance MUST appear in `stale_facts[]` with its age, and the console MUST show it before the answer rather than inside it. The module's own store and the `FreezeState` table are **not** ports: a `FreezeState` read failure is a `503` with a problem-details body and **no** `Decision` is produced, because a decision reached without knowing whether a freeze is active is not a decision.
- **Trade-off:** an outage of any fail-closed port refuses **every** request, including legitimate ones, so the service is unavailable in exactly the way that is safest and most conspicuous — 37 students are refused simultaneously and the console names the failing port. `ADMISSION_STALE_TOLERANT` on the catalogue means a decision can rest on catalogue data up to 6 hours old, which is a correctness exposure bounded only by the declared tolerance and the visibility of the amber staleness chip; a catalogue change published at 08:00 may not take effect until 14:00, and no test can detect that class of error because the fact set is internally consistent. The six-hour admission tolerance is the number a reader should argue with: it is the one place where this module trades a fresh catalogue for availability, and §12 records it as an open item for Dr. Rebecca Reed.
- **Enforced by:** `test/arch/ad4-register.test.ts` (every adapter in the code appears in the register; the register has no row with no adapter) · `test/arch/ad4-port-failure.test.ts` (**10 rows × {transport error, over-age cached value, `200`-with-malformed-body, `404` negative body}**, with the four `max_age` boundary cases per `ADMISSION_STALE_TOLERANT` row, asserting the exact outcome per cell) · `test/arch/ad4-payload-schema.test.ts` (every adapter's payload schema rejects a truncated body; a malformed body is classified, never passed through) · `test/props/predicate-totality.test.ts` (every predicate is total over the fact type — no absent, no `NaN`, no coercion) · `test/arch/ad4-clock-quality.test.ts` (a 2-second backward step, a `stratum 15` source, and a leap-flagged reading each produce `R-DEP-01`; the last accepted instant is not regressed) · `test/arch/ad4-dedup.test.ts` (a dependency failure produces **one** decision, not a branch plus a walk) · `test/nfr/nfr-13.test.ts` (no rule reads a capability fact from a port classified `ADMISSION_STALE_TOLERANT` for admission).

> **Why the classification is by port and not by family.** Revision 1 classified `actor`, `schedule`, `freeze`, `quota` as "authorization-class" and `fleet`, `catalog`, `clock` as exceptions, with one tolerance each. It contradicted `prd.md` FR-10's authoritative table on four of eight ports — most materially, it treated the catalogue as admissible for 24 hours where FR-10 says 6 — and it reinstated the family-name scheme that `prd.md` NFR-13 was written to delete, because a rule declares its **inputs**, not its family. It also classified the `FreezeState` **table** as a fail-closed "port" with a 2 s retry, which is meaningless for an in-process table that cannot time out, while the database connection underneath every owned aggregate had no classification at all. Findings ARCH-4, ARCH-27.

### M2-AD-5 — The engine publishes obligations; it never enforces one, and it never writes another component's aggregate

- **Status:** `[ADOPTED — REVISED]`
- **Binds:** the `Constraint` type, the Decision Shell, the obligation publish, the outbox, the Gateway, M9, the Reservation Coordinator, the K8s / Kubeflow Bridge.
- **Prevents:** the engine acquiring write credentials to quota balances, reservation records, cluster state, or the journal — which would make it a second writer of four aggregates it does not own, violating SPINE rules 1, 4, 6, and `prd.md` NG-10, and putting a policy component on the cluster's write path. Also prevents the engine killing jobs itself, which would strip the "who decided this" answer that CAP-8 and CAP-10 require. Also prevents a second Policy Decision Point: if a delegate re-evaluates admission, two components can mint a final decision plus reason, and the single-PDP guarantee is gone.
- **Rule:** the module MUST hold write credentials to exactly the tables it writes, which are: `FREEZE`, `FREEZE_DRAFT`, `PREVIEW_RUN`, `POLICY_VERSION`, `DECISION_OUTBOX`, `OUTBOX_DELIVERY`, `IDEMPOTENCY_KEY`, `OBLIGATION_OBSERVATION`, and — append-only, in the one transaction of §4.2 — `DECISION`, `TRACE_ENTRY`, `CONSTRAINT`, `FACT_SNAPSHOT` (P1-ARCH-AMEND D5), plus `SUPPRESSED_RULE` and `DECISION_CITATION`, which §4.2 names in the same transaction *(these two confirmed, R1d; P1-ARCH-AMEND D5 listed only the first four)*, and `AUDIT_EVENTS` (append-only freeze lifecycle actions; S4, P2-SCHEMA-1; it exists in the schema files and is not an ER entity of §4.1). `POLICY_DOCUMENT` is loaded by the migration (seed rows, 12 documents); the running module only reads it and holds no write credentials on it (R3). It MUST NOT hold a client for any **mutating** method of any other component's API. A static check MUST fail the build if `policy/core` or `decision/shell` imports a client for a denied gRPC **service name** — `reservation.v1.Reservation/CreateReservation`, `quota.v1.Quota/Debit`, any `k8s.io` method other than `fleet.v1.Bridge/GetNodeClasses` and `queue.v1.Queue/GetQueueEstimate`, and any write on the Ledger. The allow-list is keyed on **service and method**, not on host, because `Reservation` and `Timetable` are separate services that may share a process, and a hostname list cannot tell them apart. **Reading** is not writing: consuming `job.lifecycle.v1` is a permitted read under SPINE rule 5, and a read of M3's cluster projection is a read of another component's **projection**, which SPINE rule 2 makes a legitimate input to a PDP. Every emitted constraint MUST carry a non-null `enforced_by` that resolves against the delegate registry in §5.2; a constraint without one MUST fail the `Decision` constructor. `HARD_DEADLINE`, `QUEUE_ONLY`, and `QUOTA_CAP` MUST carry a non-null `deadline`; `MODEL_VARIANT` and `RESOURCE_SUBSTITUTION` MUST NOT, because the substitution is a change to the request applied by the requester and there is nobody to signal.

  **Enforcement contract, verbatim from `prd.md` §9.2.** `valid_until` is authoritative until that instant; the **Gateway** re-submits any launch to this module after that instant rather than evaluating locally. `must_checkpoint_by` is executed by **M9** on a command from the **Reservation Coordinator**. No delegate is given, and this module never requires, the authority to evaluate admission locally (SPINE rule 7; SPINE-AD-1's rejected alternative (b), "client-side decision aggregation").
- **Trade-off:** the module cannot guarantee a deadline is honoured. If M9 does not act, this module has no recourse: it records `UNCONFIRMED` in `OBLIGATION_OBSERVATION`, publishes no ack (`obligation.ack.v1` is inbound and has no producer in V1 — confirmed, R1e), the console renders a violation state that **names which component failed to signal**, and an alarm is raised. Nothing here prevents the collision. That exposure is accepted and made countable — `obligation.ack.v1` turns it from an accepted risk into a metric with a trend — rather than engineered away, because an engine that could kill jobs would be a larger and less auditable component. Two delegates now have an obligation they did not have, and a delegate that implements it lazily reintroduces the original defect outside this module's boundary; that is the residual risk, written down. A second limit (TF-14): write grants limited to the owned tables exist only in the PostgreSQL profile; the SQLite profile has no privilege model, its schema holds only tables this module owns, and the import-graph test `ad5-write-scope.test.ts` is the only guard against a write to another component's aggregate.
- **Enforced by:** `test/arch/ad5-write-scope.test.ts` (import allow-list keyed on gRPC service name, run against the shipped module graph) · `test/arch/ad5-enforced-by.test.ts` (every constraint's `enforced_by` resolves against the §5.2 delegate registry; `HARD_DEADLINE`/`QUEUE_ONLY`/`QUOTA_CAP` carry a `deadline`; the constructor rejects a constraint without one) · `test/arch/ad5-no-local-adjudication.test.ts` (no delegate package imports `policy/core`'s evaluator — this is the test that makes "no second PDP" checkable rather than aspirational).

> **Why the re-evaluation clause was deleted.** Revision 1 said: *"A delegate that receives a `must_checkpoint_by` MUST re-evaluate admission against the live policy version at launch."* That is the M2 decision procedure re-run by a component this module does not own, in a form only M2 is authorised to perform — and SPINE rule 7 is categorical that preemption is command-driven and never inferred locally. The invariant's own trade-off paragraph then conceded the outcome: *"a delegate that implements it lazily reintroduces the defect."* An obligation no delegate can satisfy is not a mitigation. The Gateway **re-submits** instead of re-evaluating, which is an upstream call, not a local decision. Findings ARCH-17, ARCH-5-adjacent; SPINE rule 7 and rule 3 are now in §9.

### M2-AD-6 — The explanation is derived from stored evidence, never generated

- **Status:** `[ADOPTED — REVISED]`
- **Binds:** the Explanation Renderer, `POLICY_DOCUMENT`, the template registry, `DECISION.rationale`, `DECISION.next_actions`, `DECISION_CITATION`.
- **Prevents:** plausible but fabricated justifications — the characteristic failure of a policy explanation produced by a language model, which can invent a rule that does not exist, cite a document that was never written, or state a VRAM figure different from the one the rule read. Also prevents copy that differs between two identical decisions, which would break NFR-3 and make the journal self-inconsistent.
- **Rule:** the `Decision` constructor MUST reject any outcome whose `citations` array is empty. The renderer MUST build the rationale exclusively from `rationale_template[primary_rule_id]` plus the matched evidence values, and MUST contain zero model invocations, zero network calls, zero clock reads, and zero free-text generation. A CI check MUST fail the build if the renderer package imports a model client. Every `citation_id` MUST resolve to a row in `POLICY_DOCUMENT` at boot; an unresolved id MUST fail the boot validator. **There is no UI fallback**: if an unresolved citation reaches a console, that is a boot failure that already happened, and a loud chip would hide it. Every `DENY` MUST carry at least one `next_action` or the explicit sentinel `NO_ALTERNATIVE_AVAILABLE`. Every rule recorded `NOT_EVALUATED` whose predicate was satisfiable on the same snapshot MUST appear in `suppressed[]` with the fact that would have fired it, so a requester constrained by a deadline is not left to discover a second limit by running into it.
- **Trade-off:** **19** templates to author, review, translate, and keep in step with the rule text, and a rule without one is a boot failure — deliberate, because the cost of a boot failure at deploy is far below the cost of a blank explanation at 09:00 on exam day. Machine-written copy would read better to a student. The team chose reproducibility and citability over fluency and accepted that a rationale will occasionally be stiff. A template cannot adapt to a novel combination of facts, so some refusals will be correct without being individually considerate — which is why the `suppressed[]` clause exists: the facts are in the record even when the prose cannot anticipate them.
- **Enforced by:** `test/arch/ad6-citations.test.ts` (every `citation_id` in the shipped registry resolves; the constructor rejects an empty array) · `test/arch/ad6-templates.test.ts` (a golden file per rule — 19 files — so a template edit is a diff, not a pass) · `test/arch/ad6-derivation.test.ts` (the same `Decision` rendered in **two separate processes**, under **two pinned versions** and **two `LANG`/`TZ` environments**, byte-identical) · `test/arch/ad6-no-model.test.ts` (no model client in the import graph) · `test/arch/ad6-suppressed.test.ts` (a `suppressed[]` entry appears for every satisfiable-but-unreached rule).

> **Why the determinism test was rebuilt.** "1 000 renders of a fixed `Decision` in one process" is a pure function applied 1 000 times; it is identical by construction and cannot fail. The risks are cross-version, cross-locale, and cross-process — a template edited, a dependency bumped, a `toLocaleString` picking a different ICU default, a `TZ` environment difference. None of those is visible from inside one process. Findings ARCH-28, ARCH-11 (no `POLICY_DOCUMENT` store existed for the validator to read).

### M2-AD-7 — A published version is immutable, and a decision is reproducible from its recorded inputs alone

- **Status:** `[ADOPTED — REVISED]`
- **Binds:** the Rule Registry, `POLICY_VERSION`, the pinned `DecisionContext`, the `Decision` schema, the journal writer, the console's version indicator.
- **Prevents:** editing a rule in place, which would make last week's refusal unreproducible against the rule that produced it and would turn the audit log into fiction. Also prevents a half-applied version change, where a rule set is edited while an evaluation is in flight and the resulting decision matches no coherent rule set.
- **Rule:** a published version MUST be stored with a `sha256` `content_hash` computed over **the rule set, the versioned constants (`NIGHT_WINDOW`, `PROTECTION_GRACE`, `NEAR_BOUNDARY_DISPLAY_HORIZON`), `CAMPUS_TZ`, `tzdata_version`, and `engine_version`**, and marked immutable. **Any** write attempt against a referenced version MUST be rejected at the store level, by a referential check and not merely by a privilege — the two are independent and both are required. Evaluation MUST read exactly one resolved version from start to finish; a version published during an in-flight evaluation MUST NOT affect it, and the new version takes effect for decisions started after publication completes. `policy_version`, `content_hash`, `engine_version`, `campus_tz`, and `tzdata_version` MUST appear on every `Decision` and on `policy.decision.v1`. Publication MUST complete within 5 s and MUST emit `policy.version.published.v1` carrying `previous_version` and `changed_rule_ids`.
- **Trade-off:** there is no hot-patch path. A wrong rule is corrected only by publishing a new version, so the version table grows monotonically and is archived rather than pruned, and the freeze authority loses the ability to "fix it for five minutes" during an incident — which is sometimes the correct operational act and is now impossible. The 5-second activation window is a small exposure in which two processes may evaluate the same request against different versions; accepted, because the alternative (blocking publication until every process acknowledges) trades a rare inconsistency for a frequent stall. Putting `CAMPUS_TZ` in the hash means changing the campus time zone is a versioned act, which is a deliberate inconvenience: the zone decides every window test and `prd.md` A-3 marks its value unconfirmed.
- **Enforced by:** `test/arch/ad7-immutable.test.ts` (executed as a **version-admin** role that *does* hold `UPDATE` on `POLICY_VERSION`, so the rejection observed is the referential one and not `permission denied` — revision 1's test used the journal role, whose lack of `UPDATE` made the grant reject the write before the invariant was ever exercised) · `test/arch/ad7-reproducible.test.ts` (a stored decision re-evaluates byte-identically given `(rule set, constants, campus_tz, engine_version)`, and fails if any one of them is altered) · `test/arch/ad7-pinning.test.ts` (an evaluation spanning a publication records exactly one version on both the decision and the outbox row) · `test/nfr/nfr-7.test.ts` (publication ≤ 5 s).

> **Why `content_hash` had to widen.** Revision 1 hashed *"the rule set"* and hard-coded a 300-second grace in the invariant clause, outside the hash. `PROTECTION_GRACE` appears in two predicates and shifts every boundary-derived `valid_until` by five minutes, so last week's refusal was reproducible only if you happened to be running the same **binary** — and a deploy is invisible in the journal. The same applied to `CAMPUS_TZ`: two instances with different zones produced different decisions from identical inputs and the same `policy_version`, and nothing in the contract could say why. Findings ARCH-26, ARCH-20.

### M2-AD-8 — The outbox is append-only, one idempotency key yields one decision, and the record holds ids only

- **Status:** `[ADOPTED — REVISED]`
- **Binds:** the outbox writer, `DECISION_OUTBOX`, `OUTBOX_DELIVERY`, `IDEMPOTENCY_KEY`, `FACT_SNAPSHOT`, `OBLIGATION_OBSERVATION`, the event payload, the module's database role.
- **Prevents:** post-hoc editing or deletion of a decision record — Dr. Rebecca Reed disagreeing with a refusal and editing the row. Also prevents one attempt a reader can see producing three audit records, and prevents personal data entering a store that has no deletion path.
- **Rule:** the module's database role MUST have `INSERT` and `SELECT` on every owned table and MUST NOT have `UPDATE` or `DELETE` on `DECISION_OUTBOX`, `OUTBOX_DELIVERY`, `IDEMPOTENCY_KEY`, `OBLIGATION_OBSERVATION`, `POLICY_VERSION`, `DECISION`, `TRACE_ENTRY`, `CONSTRAINT`, `FACT_SNAPSHOT`, `SUPPRESSED_RULE`, `DECISION_CITATION`, or `AUDIT_EVENTS` (P1-ARCH-AMEND D3, D5; P2-SCHEMA-2 M1, S4). Delivery state is one `OUTBOX_DELIVERY` row per attempt, so `DECISION_OUTBOX` itself is never updated. A deployment check MUST assert this against the live role's grants **on the integrated target**, and the standalone prototype MUST carry the equivalent control as a `BEFORE UPDATE` / `BEFORE DELETE` trigger that raises, since the prototype engine has no roles. The outbox API MUST expose no mutating route. `IDEMPOTENCY_KEY` MUST be `UNIQUE` on `(actor_id, key)` and is the single uniqueness home *(confirmed, R1a)*; it stores the request body hash and a 24-hour `replay_window_expires_at`; a replay inside the window MUST return the original `Decision` without re-evaluating, and a replay carrying a different body for the same key MUST be `409`. There are no server-derived keys. A derived decision — an auto-proposed alternative — MUST be stored with `parent_kind = DERIVED`, a non-null `derived_from`, and `depth = 1`, and MUST NOT create a second top-level record. `decision_id` MUST be monotonic (`uuid7`). The `FACT_SNAPSHOT` MUST be a typed projection onto an explicit field allow-list, and a check MUST assert that no key outside that list is present at write time: **the record contains actor ids only** — names, addresses, tokens, and keys are never persisted, returned, or logged.

**Three further clauses, each closing a way the record can lie.** (a) The append is **one transaction** covering the decision, its trace, its constraints, its suppressed set, its citations, and its snapshot; a `DENY` whose evidence was never stored is a refusal nobody can reproduce, and the failure that produces it is a crash between two writes. Eviction is bounded by `retention(window) = max(decision_retention, snapshot_retention)`, sets `snapshot_retained = false`, and a read of an evicted snapshot returns `410 SNAPSHOT_EVICTED` — a different statement from `404` and from a fault, because "this refusal can no longer be reproduced" is not "no such decision". (b) **No IEEE-754 double crosses the journal boundary**: integers carry the unit in the name, decimals declare a scale. `NFR-3` is measured through a `jsonb` column whose number rendering is not IEEE-754 round-tripping, so a single float turns a SQLite→PostgreSQL adapter swap into an intermittent determinism failure that reads as an engine defect. (c) A derived decision records **both** principals: `originating_actor_id` (the human it is for) and `submitted_by ∈ {HUMAN, SYSTEM}`. Without both, an auto-proposed alternative submitted for Elena Vargas is either absent from her journal or indistinguishable from a submission she made, and the ids-only discipline gives an auditor no way to see that no human touched it.

**Three trace states, not four.** `MATCH`, `NO_MATCH`, `NOT_EVALUATED` — and no `INDETERMINATE`. A fourth state was declared by both documents and produced by neither, and its removal is not a simplification: a fact that is present but untrustworthy is already represented by `stale_facts[]` and by the fail mode the port register assigns it, so the state carried no information a reader could act on, while a `NOT_EVALUATED` count assertion silently assumed the other two were the only possibilities. Finding EDGE-34.
- **Trade-off:** there is no erasure path for personal data held inside a historical decision record. The mitigation is to store as little as possible at the storage layer rather than to add a deletion mechanism, which is a privacy trade made at the wrong layer and is recorded as such. The outbox grows without bound and requires retention this module does not own; because the **Audit Ledger** owns the journal and its history, the retention horizon is the Ledger's decision and this module's guarantee is scoped to *"while the window is within the retention horizon"* — revision 1 claimed bit-identical results forever from a table it did not own and could not partition. Ordering by `uuid7` is stable and close to chronological, but it is still only as good as the clock, and a clock that steps backwards produces an order no reader would call chronological: visible, not corrected. Requiring an `Idempotency-Key` adds a header to every call; the alternative was three records per retry.
- **Enforced by:** `test/arch/ad8-grants.test.ts` *(integration profile; asserted against PostgreSQL and tagged as excluded from the standalone launcher, because SQLite has no roles and revision 1's test therefore could not run in the one environment the document said would be used)* · `test/arch/ad8-immutable.test.ts` *(standalone profile; the trigger rejects an `UPDATE` on the outbox)* · `test/arch/ad8-idempotence.test.ts` (three `POST`s with one key produce one `decision_id`, one outbox row, one `policy.decision.v1`; a different body on the same key is `409`) · `test/arch/ad8-derived.test.ts` (an auto-proposed alternative creates no second top-level record — asserted against `parent_kind` and `depth`, terms the schema now defines) · `test/nfr/nfr-5.test.ts` (**allow-list equality** over 10 000 generated decisions, plus a deny-list pass as a second belt).

> **Why this invariant is not what it was.** Revision 1's `AD-8` combined four claims: journal grants, a bit-identical repeat query, a derived-entry rule, and PII scrubbing — against a query surface this module does not own. Removing the query surface removed the determinism clause entirely, because there is no longer a result set here to order. What remains is a **delivery** invariant, and its two live risks are the ones a delivery component actually has: duplicate delivery under retry, and personal data arriving through a passthrough column. The `nfr-5` proof also changed direction: searching for deliberately poisoned strings finds only the leaks the test author imagined, so the test now asserts the field set **equals** the allow-list, and a field nobody thought to poison fails it. Findings ARCH-2, ARCH-10, ARCH-21, ARCH-29.

### M2-AD-9 — Every route is authenticated, the session actor is authoritative, and the freeze's preview is a server-enforced precondition

- **Status:** `[ADOPTED — NEW]`
- **Binds:** all 13 routes, the Gateway's Identity Adapter, the session actor, `R-VALID-01`, the draft → preview → activate sequence, `PREVIEW_TOKEN_TTL`, the `FREEZE` store's `CHECK`s and partial unique index.
- **Prevents:** the module's only irreversible action — activating an emergency freeze that refuses every non-examination request — being performed by an unauthenticated caller, on a draft whose consequences were never computed, or on behalf of an actor the caller chose. Also prevents a caller asserting its own identity inside the request body, which would make every authorisation rule in the catalogue decorative.
- **Rule:** every route requires an authenticated caller, except `GET /health` and `GET /ready`, which need no authentication (P1-ARCH-AMEND D4). The **Gateway** authenticates and injects the session actor (SPINE-AD-8); M2 resolves academic context read-only through M1's ports and holds no identity fact of its own. A `Request.actor_ref` that differs from the session actor is `DENY(INVALID_REQUEST)` by `R-VALID-01` at precedence −1, journalled and attributed like any other decision — **not** a transport error. `POST /policy/freezes/{id}/activate` and `POST /policy/freezes/{id}/lift` additionally require `role_tier ≥ INSTRUCTOR` with a `LAB_OPERATOR` scope (the §5.1 predicate; P1-ARCH-AMEND D4). Freeze activation MUST be a three-step, server-enforced sequence: `POST /policy/freezes` creates a `FreezeDraft`; `POST /policy/freezes/preview` persists a `PreviewRun` and returns a token that carries the `preview_run_id`, signed with `HMAC(server_secret, draft_id ‖ content_hash ‖ actor_id ‖ issued_at)`, with a 60 s TTL; `POST /policy/freezes/{id}/activate` recomputes the HMAC, locates the `PreviewRun` by `preview_run_id`, checks signature, actor, expiry, consumption and the draft's `content_hash`, marks it consumed, and only then activates. A missing, expired, consumed, or hash-mismatched token is `409`. Re-previewing issues a fresh token, so an interrupted confirmation flow is recoverable.

**The preview token is a freshness token, not an authorisation token.** All four freeze-mutating routes and both freeze read routes require `role_tier ≥ INSTRUCTOR` with a `LAB_OPERATOR` scope, and activation **re-reads the tier fresh** — never the preview's snapshot, because the window between a preview and an activation is precisely the window in which a revocation lands, and a token that survives it for its remaining 60 seconds is the whole of the gap. The token is additionally bound to `actor_id`, is **single-use** (`consumed_at` written in the activation transaction, a second presentation is `409 TOKEN_CONSUMED`), and is valid at exactly `issued_at + 60 s`. The `409` for a duplicate active freeze comes from a partial unique index on the normalised scope key rather than from a prior read, because a read-then-write check is defeated by a double-tap and two `ACTIVE` freezes with identical scope make every subsequent `R-FRZ-01` decision's cited `freeze_id` ambiguous. A `DRAFT` carries `expires_at = created_at + 24 h` and activation requires `ends_at > campus_now` server-side; a draft is a loaded action, and an abandoned one must not be sitting in the store where a later press picks it up. Finding EDGE-7, EDGE-17, EDGE-31.
- **Trade-off:** the three-step sequence is three round trips and 60 seconds of patience in front of the module's one irreversible action, and Dr. Rebecca Reed, interrupted at the reason field, restarts the preview. That is the price of a server-enforced precondition: a UI convention can be skipped by `curl`, and a convention that can be skipped is not a control. The `Idempotency-Key` requirement and the actor-binding rule add a header and a field check to every call, and a client that omits the header must learn the server-derived fallback. `R-VALID-01` returning a journalled `DENY` rather than a `400` means a client with a bug generates journal entries; that is the intended behaviour, because a malformed request is the class most worth auditing.
- **Enforced by:** `test/arch/ad9-auth.test.ts` (the 11 authenticated routes in §5.1 — `POST /policy/decisions`, `POST /policy/decisions/preview`, `GET /policy/rules`, `GET /policy/versions`, `GET /policy/versions/{v}`, `POST /policy/freezes`, `POST /policy/freezes/preview`, `POST /policy/freezes/{id}/activate`, `POST /policy/freezes/{id}/lift`, `GET /policy/freezes`, `GET /policy/freezes/{id}` — reject an unauthenticated caller, and `GET /health` / `GET /ready` accept one; the six freeze routes reject a `STUDENT` session) · `test/scenario/sa-5.test.ts` (activation with the preview call stubbed to fail is blocked; a token whose hash does not match the draft is blocked; an expired token is blocked; a token issued for one actor and presented by another is blocked; a second presentation of a consumed token is blocked; three activations of one draft yield one freeze) · `test/arch/ad9-role-revocation.test.ts` (the tier is revoked between preview and activation; activation is `403`) · `test/arch/ad9-freeze-concurrency.test.ts` (8 simultaneous activations of one scope → exactly one `201`, seven `409`s) · `test/arch/ad9-actor-binding.test.ts` (a `Request.actor_ref` differing from the session actor is `R-VALID-01`, and is present in the journal) · `test/arch/ad9-scope-predicate.test.ts` (the §4.2 `in_scope` disjunction, its three `CHECK`s, and the rejection of a past-window activation).

> **Why this invariant is new.** Revision 1's §5.1 listed twelve routes with no authentication column at all, and its own §9 deferred identity on the incorrect grounds that the spine's `AD-8` Identity Adapter port was *"that same port"* M2 reads its actor fact through. The spine's adapter sits in front of the PDP and turns a token into an identity; M2's actor port is M1's. Conflating them papered over the part that was actually missing, which was that no component in the document was responsible for authenticating anything. Findings ARCH-30, ARCH-7.

## 7. Technology Stack

**Stack revision (Phase 0, Solu-2).** Revision 3 declared Go 1.23+; the language was changed to TypeScript on Node.js by human decision because Solu-2 allows only Python or TypeScript. Only text specific to the old stack was changed; nothing was renumbered. Rows marked *proposed* are TypeScript equivalents of Go features and await human confirmation.

**Stack Decisions**

```
Language:       TypeScript on Node.js
Web framework:  Express
Persistence:    PostgreSQL 16 (integrated) / SQLite WAL (standalone), one repository interface; pg + better-sqlite3, plain SQL, no ORM
Tests:          Vitest + fast-check
Time:           Clock and IdGenerator ports are the only sources of time and randomness; campus.clock (port #10) unchanged
```

|---|---|---|
| Language | **TypeScript on Node.js** | Decided by the human at Solu-2 Phase 0 (see "Stack revision" above). The reasoning for leaving Go is the human's to record in `ai-log/decision-log.md`; this row records only the fact. Revision 3 of this row read "Go 1.23+, matches `ARCHITECTURE-SPINE.md`'s technology stack"; that is now a deviation, recorded in §9. |

| Rule engine shape | **data-defined rules + one fixed precedence walker** | Rules are data, so the catalogue is renderable in UX-2, diffable into `changed_rule_ids`, hashable for `M2-AD-7`, and inspectable by someone who does not write Go. None of that is true of rules expressed as a chain of `if` statements. |
| Ports and fixtures | a `Port` interface per fact source, with a fixture-backed **stub server on a bound TCP socket** | This is how "independently runnable" is achieved without mocking the engine: the core receives a fact set, so swapping the cluster for a JSON file changes only the shell — and the stub listens on a socket rather than being an in-process double, so `prd.md` NFR-11's clause that ports are not a compile-time fiction is actually exercised. |
| Validation | **three** layers, one job each: **protobuf** owns the wire shape (does the body parse?); each **port adapter** owns its payload schema (is this fact well-formed, and is the answer `ok`, `notFound`, or an error?); and `R-VALID-01` owns policy validity (does `exam_binding` resolve to an `ACTIVE` reservation? does `subject_id` resolve? does the actor match the session? does the `model_ref` exist?) | Revision 1 ran one validator in the shell, which both violated the shell's own "decides nothing" clause and left the most suspicious request class — a client hammering a broken endpoint — with no journal entry at all. `INVALID_REQUEST` is a **cited, attributed, journalled** decision. The middle layer is what stops a truncated HTTP 200 from becoming a `NaN` that fails open, and it is the only layer that distinguishes *this thing does not exist* from *this thing could not be fetched*. |
| Storage | **PostgreSQL 16 for the integrated deployment; SQLite in WAL mode for the standalone prototype**, behind one repository interface | PostgreSQL is required for the role-grant control that is the module's strongest integrity claim and that SQLite does not have. SQLite keeps the standalone launcher at zero external services. §11 tags each storage proof with the profile it runs in, because revision 1 asserted a grants test in an environment where grants do not exist. |
| Web framework | **Express** | Decided by the human at Solu-2 Phase 0. Serves the 13 routes of §5.1. |
| Data access | **`pg`** (PostgreSQL) and **`better-sqlite3`** (SQLite), plain SQL behind the one repository interface; **no ORM and no query builder in this unit**. One migration file per engine: `001_m2_schema.pg.sql` and `001_m2_schema.sqlite.sql` | The two engines differ (`jsonb`, `timestamptz`, exclusion constraints and triggers have no SQLite spelling), so each gets its own file. Kysely is deferred to implementation. |
| Event bus | **NATS JetStream**, per SPINE-AD-2 | Durable delivery for `at-least-once`, and the publisher in §5.3 is a thin client over it. |
| Console | a web client consuming **only** the public API in §5.1 plus the Audit Ledger's query surface | Enforces that the console cannot reach behind the engine: if a feature is impossible through the API, it is not built. |
| CLI | a Node CLI, `aegis`, importing the same `policy/core` package | `aegis eval --request r.json --at 2026-04-08T22:10:44.900-05:00` is the shortest path to reproducing a boundary defect, and the clock override is how the four evaluations in `ux/C-UX-Scenarios/scenario-3.md` are performed. |
| Explanation | pre-compiled TypeScript template functions, one per rule, registered at boot *(proposed, to be confirmed by the human; replaces Go `text/template`)* | A missing template is a boot failure (`M2-AD-6`), not a blank card at 09:00 on exam day. |
| Time | A `Clock` port and an `IdGenerator` port are the only sources of time and randomness; port #10 `campus.clock` stays as defined in §2.1.1. UTC instants internally, campus-local only at the edges, with IANA zone data supplied by a version-pinned source whose version is recorded as `tzdata_version` *(proposed, to be confirmed by the human; replaces Go embedded `time/tzdata`)* | `M2-AD-3`'s two representations. Pinning the zone database is what removes a host-package dependency from the campus-local half. |
| Tests | **Vitest**, with **fast-check** for property-based generation of boundary instants | `NFR-4` is a property over generated instants, not six hand-written cases. fast-check is the library the Solu-2 assignment names for the TypeScript option. |

## 8. Component Topology and Technology Rationale (alternatives considered)

Required by Phase 3: *"Challenge the AI to present 2–3 architectural alternatives, critically evaluate trade-offs, select the optimal design, and justify your choice."* Each decision below names the option that would actually have changed the outcome. A third option that exists only to be knocked down is padding, and in two cases below the original third option was one.

### 8.1 How the rule set is expressed

| Option | Shape | What it buys | What it costs | Verdict |
|---|---|---|---|---|
| **A. Data-defined rules + a fixed precedence walker** *(selected)* | Rules are records — `{id, precedence, when, outcome, constraints, citations, template, inputs[]}` — interpreted by one walker | Renderable (UX-2), diffable into `changed_rule_ids`, hashable for `M2-AD-7`, inspectable by someone who does not write Go, and the `inputs[]` field is what makes `NFR-13`'s inheritance check writable at all. `M2-AD-2` is enforceable at boot. | A small interpretive tax: an unusual predicate means extending the predicate vocabulary, and a `when` that strays into arbitrary code defeats the design. | **Selected.** The institutional requirement is that a professor can read the rules, and a chain of `if` statements cannot be rendered, diffed, or hashed. |
| B. Compiled chain — one function per rule, hand-ordered in source | `var rules = []Rule{freeze, tier, auth, lab, night, …}` | Quickest to write, no interpretive overhead, full type checking on each condition | Precedence is implicit in array position, so a duplicate is invisible until a decision differs between two replicas; versions are diffs of code; the catalogue must be **duplicated** as prose and will drift from the code. | Rejected. Optimises for the implementer and pays in the one place drift is unaffordable: the rule text. |
| C. External rules engine (Rego-shaped) | Rules in a host language, evaluated by a third-party interpreter | Mature optimisation, decision logs built in | **Rule text stops being data and becomes a program.** `changed_rule_ids` degrades to a source diff, `content_hash` covers a build rather than an artefact, UX-2's professor-readable rendering becomes a re-implementation, and the boot validator in `M2-AD-2` becomes a property of someone else's release schedule. | Rejected, and the cost is stated as rule-text-as-program rather than as a second language — a team of 2–4 would notice the language and reason least about the property, which is the one that actually decides it. |
| D. **Build-time code generation from the same data catalogue** | A generator reads the catalogue and emits a typed walker; the catalogue remains the source of truth | Keeps rules as data — so `M2-AD-2`, `M2-AD-7`, and UX-2 all still hold — while removing A's interpretive tax and giving every predicate a compile-time-checked signature | A build step, and a generator that must be trusted to stay in step with the catalogue | **Not selected, recorded as the runner-up.** It dominates A on the interpretive tax and gives up nothing on auditability, so if the predicate vocabulary grows past roughly 25 rules this becomes the better answer. At 19 rules the generator is a second thing to keep in step, and the interpretive tax is a bounded, local cost. The decision is revisited at 25 rules, and that threshold is written down here so the revisit is a commitment rather than a mood. |

### 8.2 Where the fact fetch lives

| Option | What it buys | What it costs | Verdict |
|---|---|---|---|
| **A. The shell fetches all 10 rows of the register; the core receives an immutable `DecisionContext`** *(selected)* | The core stays pure; the engine is testable with a literal context and no doubles; a port failure is a shell concern and is handled by `M2-AD-4` without touching the core | One allocation per evaluation; the context is a trust boundary, so every adapter schema-validates before the fact enters it | **Selected.** Purity is the property that makes every other invariant testable. |
| B. The core receives a `PortProvider` and calls it | No marshalling; a rule fetches only what it reads | The core is no longer pure; testing one rule requires a live provider; `M2-AD-1` becomes unenforceable; and a rule's own I/O would put a network call on the NFR-1 latency path | Rejected. The marshalling cost is small next to losing the property that makes the rule matrix testable at all. |
| C. An event-sourced fact projection maintained by the shell | Naturally consistent snapshots and no fan-out latency | One projection per port — nine more components — to serve a read that must complete inside `FACT_TIMEOUT_MS = 40` | Rejected. `AD-6` permits async propagation for **usage**; admission needs a synchronous read, and a projection adds a staleness class `M2-AD-4` does not model. |

### 8.3 The `CONSTRAIN` outcome's execution model

| Option | What it buys | What it costs | Verdict |
|---|---|---|---|
| **A. The engine returns constraints; delegates enforce; the console shows violations** *(selected)* | Honours SPINE-AD-1, -4, -5; the core stays pure; a missed deadline becomes a visible, attributable record rather than a hidden failure | The module cannot guarantee its own deadlines (`M2-AD-5` trade-off) | **Selected.** |
| B. The engine writes the constraint into the delegate's queue and polls for compliance | End-to-end ownership of the outcome | Turns the engine into a stateful writer of two other aggregates; violates SPINE rule 6; a slow delegate becomes the engine's availability problem | Rejected on upstream-contract grounds, independent of engineering merit. |
| C. The engine opens an unbounded `ALLOW` and trusts the delegate to re-check | Simplest possible design | Exactly the failure the module exists to prevent, and the delegate is forbidden from re-checking (SPINE rule 7) | Rejected. Recorded in full in `ux/C-UX-Scenarios/scenario-3.md` §5 as findings `UX-S3-02` and `UX-S3-04`, and in `ai-log/decision-log.md` as **L-11**. *(Revision 1 cited `UX-S3-02` here, which is about a missing bound inside a rule and has nothing to do with an unbounded `ALLOW`; the citation was wrong and is corrected.)* |
| D. **Acknowledgement on the bus** | The delegate publishes `obligation.ack.v1`; the module journals it, and a miss becomes a metric with a trend rather than an accepted risk | One event and one table, and a schema change to the delegate's contract that this module cannot force | **Not selected for V1, and this is the runner-up.** It is the only option that makes the `M2-AD-5` residual exposure measurable, and the exposure is measurable. It is deferred rather than rejected because it needs a change on the M9 side of the contract, which is a different team, and shipping half of it — an event with no producer — would be worse than not shipping it. The `OBLIGATION_OBSERVATION` table and the `UNCONFIRMED` state are built now so that adding the event later is a producer change and not a migration. |

### 8.4 Storage engine

| Option | What it buys | What it costs | Verdict |
|---|---|---|---|
| **A. PostgreSQL 16, with a role whose grants are the control** *(selected for integrated)* | Role grants are the strongest append-only control available, and SPINE-AD-9 names this target | An external service for the standalone launcher | **Selected for the integrated deployment.** |
| B. SQLite in WAL mode, with `BEFORE UPDATE` / `BEFORE DELETE` triggers raising | Zero external services, which is what makes the standalone launcher work; triggers are a database-level control, not a convention | No roles, so the grant-based control has no equivalent; concurrent writers are serialised | **Selected for the standalone prototype.** This is a profile split, not a preference, and §11 tags each storage proof with the profile it runs in. |
| C. An append-only file per decision plus an index | Trivially append-only; no database | No query path this module would own (it does not own one); no referential constraint for `M2-AD-7`; the freeze aggregate needs transactions | Rejected. |

### 8.5 The event bus and the delivery publisher

| Option | What it buys | What it costs | Verdict |
|---|---|---|---|
| **A. NATS JetStream + an in-process outbox** *(selected)* | Durable, at-least-once, consumer-agnostic; matches SPINE-AD-2 | An external service in the standalone profile; an outbox component with a buffer, a lag metric, and an alarm (§5.3) | **Selected.** The outbox is unavoidable: NP-10 forbids failing a request on a bus outage, and something must hold the events. |
| B. Write the journal row synchronously, publish on commit | One fewer component; the journal is the record and the event is derived from it | The module does not own the journal (NG-10), and a synchronous write puts a disk round trip on the NFR-1 latency path — which is precisely the inversion `prd.md` finding PRD-16 removed | Rejected. |
| C. Fire-and-forget publish with no buffer | No component | A bus outage loses decisions, and a lost refusal is a refusal nobody can audit | Rejected. |

### 8.6 How `preview_token` is constructed

| Option | What it buys | What it costs | Verdict |
|---|---|---|---|
| **A. Server-issued `HMAC(server_secret, draft_id ‖ content_hash ‖ actor_id ‖ issued_at)` over a persisted `PreviewRun`, carrying its `preview_run_id` (TF-7)** *(selected)* | Falsifiable: no `PreviewRun` row means no token, so "activation with the preview stubbed to fail is blocked" is a test that can fail. A client cannot forge it. | A server secret to manage and rotate; a persisted row per preview | **Selected.** |
| B. `sha256(canonical_json(draft))` with a TTL | No server state; the client can compute it | **It proves only that the caller knows the draft** — which the caller already knows, and can compute offline without ever calling the preview route | Rejected. This is what revision 1 specified, and its own justification — *"a caller using `curl` cannot skip the preview either"* — is false for it. Finding ARCH-7. |
| C. A boolean `previewed: true` flag on the draft | Simplest | The client sets the flag | Rejected. |

### 8.7 Whether `CAMPUS_TZ` is versioned

| Option | What it buys | What it costs | Verdict |
|---|---|---|---|
| **A. Include `CAMPUS_TZ` in `content_hash` and on every `Decision`** *(selected)* | A decision is reproducible from its recorded inputs alone (`M2-AD-7`); a zone change is a versioned act with a diff | Changing the zone requires a publication, which is friction for a configuration value | **Selected**, and the friction is the point: the zone decides every window test, so it is a policy input wearing a configuration label. `prd.md` A-3 marks the value unconfirmed, which is a further reason to version it — an unconfirmed value should not be free to change. |
| B. Keep it in deployment configuration and record it on the decision without hashing it | Cheaper to change | Two instances with different zones produce different decisions from identical inputs and the same `policy_version`, and nothing in the record explains why | Rejected. |

### 8.8 How a port outcome is classified

| Option | What it buys | What it costs | Verdict |
|---|---|---|---|
| **A. Four typed shapes — `ok`, `notFound`, transport error, `ok(malformed)` — each with a declared mapping** *(selected)* | A mistyped identifier becomes a cited `DENY` by `R-VALID-01` instead of a system fault; a truncated body becomes a classified error instead of a `NaN` that fails open; an over-age cache is an error instead of a fact; and a missing entity is never served from a cache carrying a revoked licence | Every adapter declares its own `notFound` semantics, and the register test has to read those declarations | **Selected.** Three of the four shapes are the ones a two-valued `ok`/`error` port cannot express, and each of the three corresponds to a wrong decision the two-valued version produces. |
| B. Two shapes — `ok` / `error`, with the adapter deciding what counts as an error | Minimal adapter code | Exactly the three wrong decisions above. A 404 becomes a retry, a retry becomes a cached copy, and the cached copy of a deleted model carries the licence that was revoked yesterday | Rejected. |
| C. Fail closed on everything: any non-`ok` shape is `R-DEP-01` | One rule, no mapping table | An unprovisioned account is told to retry three times and then to contact support, instead of being told it is not enrolled; and a request for a model the catalogue has never heard of isodel is attributed to the dependency rather than to the request | Rejected for `notFound` specifically. The right answer to "there is no such model" is a refusal that names the model, and a `DEPENDENCY_UNAVAILABLE` cause sends the escalation to a platform team that cannot fix a typo. |

### 8.9 When the evaluation instant is read

| Option | What it buys | What it costs | Verdict |
|---|---|---|---|
| **A. Read the clock first, before any other fact fetch; that single instant is `evaluated_at`** *(selected)* | The decision is anchored to the moment the request arrived rather than to the moment the slowest dependency replied, which makes the outcome independent of the shell's fan-out order | The clock call is serialised ahead of the fan-out, adding its own latency to the critical path | **Selected.** `FACT_TIMEOUT_MS` is 40 ms and the clock is local, so the serialised cost is small next to the alternative: read last, a request arriving at 08:59:59.900 with a 140 ms slowest port is evaluated at 09:00:00.040 and denied by a rule that would not have matched at arrival. That is `M2-AD-1`'s named failure — the same request with a different answer depending on which part of the shell was slowest. |
| B. Read the clock last, so the instant reflects the freshest facts | The clock reading is the newest of the ten facts | Trades a 1 ms boundary-precision policy for the removal of one serialised call, and makes the answer a function of the slowest dependency | Rejected. |
| C. Read the clock at the Gateway and pass the instant in | The Gateway's time is the client's time | A caller-supplied clock is the cheapest freeze bypass in the module: one parameter walks around `R-NIGHT-01` and `R-LAB-01` and writes a forged `evaluated_at` into the journal. The only permitted override is the preview route's, gated on tier and deployment profile, and it is recorded as an override. | Rejected on `M2-AD-1` grounds. |

## 11. Verification Plan

Three columns, because a list of test names invites the belief that something is covered. The third column is the one that matters: **if this test passes while the requirement is broken, the test is wrong, and the row is a defect.** Revision 1's plan had two columns and, on inspection, **0 of 10 named mechanisms could fail for the reason stated** — one was defeated by a one-line alias, one could not run in the environment the document named, three were structurally incapable of failing, one was unmeasurable, and two asserted superseded targets.

| Requirement | Test id | What fails if the requirement is broken |
|---|---|---|
| `M2-AD-1` purity | `ad1-imports.test.ts` | The import allow-list is evaluated against the shipped module graph, not a fixture. A new import of `net`, `time`, a driver, or a gRPC client fails the build. Aliasing a symbol does not defeat it, because it is a property of the graph. |
| `M2-AD-1` purity (dynamic) | `ad1-offline.test.ts` | `evaluate()` is driven with the fixtures directory made unreadable and no network reachable. Any I/O in the core surfaces as an error rather than as a pass. |
| `M2-AD-1` attribution | `ad1-trace-complete.test.ts` | Removing one rule from a fixture registry must drop the `NOT_EVALUATED` count by exactly one and leave `primary_rule_id` unchanged. A walker that short-circuits without recording the tail fails; a walker that records the tail as `NO_MATCH` fails. |
| `M2-AD-2` order | `ad2-precedence.test.ts` | Four fixtures, four failures: a duplicate precedence, an out-of-range value, a missing citation, an unresolved `doc_id`. |
| `M2-AD-2` on the shipped registry | `ad2-shipped-registry.test.ts` | The validator runs on the registry that ships and must pass; a negative fixture with a rule at precedence −1 must also pass, so the range cannot be narrowed back to `[1, 1000]` without failing here. |
| `M2-AD-2` no dead rules | `ad2-subsumption.test.ts` | A pairwise subsumption check over the catalogue's declared predicate metadata. A new rule that can never fire fails the build instead of shipping as a comment. |
| `M2-AD-3` boundaries | `ad3-boundary.test.ts` | 1 000 generated instants × **6 enumerated** boundary kinds, expected value **computed independently of the engine**. A third outcome flip beyond the two permitted fails. |
| `M2-AD-3` two representations | `ad3-dst.test.ts` | Under a DST zone, the wall-clock branch and the instant branch are asserted to disagree, and the bounding path is asserted to use the instant branch. This is the test revision 1 could not have failed. |
| `M2-AD-3` past bound | `ad3-past-bound.test.ts` | A window fully in the past is excluded from `B`; a boundary inside the grace band yields `ALLOW` with `valid_until = campus_now`, never a `CONSTRAIN` with an expired deadline. |
| `M2-AD-3` one deadline | `props/single-deadline.test.ts` | Over 10 000 generated contexts, `must_checkpoint_by = valid_until` in 100 % of cases. A rule that computes its own deadline from its own boundary list fails on the first context where the two disagree. |
| `M2-AD-3` rendering | `ad3-render.test.ts` | The same instant rendered under two `TZ` environments produces the same campus-local string, so a renderer that forgets to convert is caught. |
| `M2-AD-4` register | `ad4-register.test.ts` | Every adapter in the code has a register row and every register row has an adapter. "100 % of registered ports" becomes measurable because *registered* is defined as *a row in the register*. |

**Enforceability audit.** Every row above was checked for one question: *if the requirement is broken, does this test fail?* Six rows in revision 1 did not, and they were the six named as the proof of the module's most-cited properties. Three are structurally incapable of failing (`ad7-immutable` — the grant rejects the write before the check runs; `ad8-idempotence` — `evaluated_at` is inside the pinned fact set, so a repeat necessarily matches; `ad6-derivation` — a pure function applied 1 000 times in one process), one is structurally incapable of running (`ad8-grants` — SQLite has no roles), one is unmeasurable (`ad4-classification` — "100 % of registered ports" with no register), and one is defeated by a one-line alias (`ad1-purity`). Each of the six has been replaced by a mechanism that can fail, and this audit is repeated at the readiness gate rather than assumed to have been done once.

**What the edge-case pass changed about this audit.** The second review was handed the revision-2 document and found 35 defects, of which **7 were already closed by revision 3's own rewrite** and **2 rested on a stale premise** — the review quoted `R-FRZ-01`'s condition without its half-open test and the enclosing access window's definition, both of which `prd.md` §6.2/§6.3 carry and revision 2 merely summarised. Two of the four Criticals it called *structurally guaranteed* — the unreachable `ALLOW` and the past-dated `valid_until` — were closed by that same rewrite, which is the strongest available evidence that the review's method is sound and that the remaining 28 are the ones that survived it. The lesson carried into the readiness gate: a review pass is a measurement, and a measurement taken against a document that has since changed is a measurement of the wrong thing. Every figure in this document is therefore stated with the revision it was taken against.
