## 1. Reading rules

1. `AR` = `planning/ARCHITECTURE.md`; `PRD` = `planning/prd.md`; `UX` = `ux/EXPERIENCE.md`. A clause cites its source as `AR §n`, `PRD §n`, `PRD FR-n`, `PRD NFR-n`, `PRD R-<id>`.
2. A clause marked `(identifier assigned here)` names a code that the files do not name; its trigger is taken from a quoted sentence. A clause marked `(status not stated)` means the cited file gives no HTTP status for that case; the catalog row repeats it and Section 6 lists it.
3. `retryable = Y` means: repeating the identical call, with no change by the caller, can succeed once the dependency recovers or `retry_after_ms` has elapsed. A call that needs a different request, a new preview, or a human action is `N`.
4. Every interval `[start, end)` is half-open (`PRD` §6.4). Time clauses use the Clock port `campus.clock` (`AR` §2.1.1, port 10). Identifiers (`decision_id`, `draft_id`, `freeze_id`, `preview_run_id`) come from the `IdGenerator` port (`AR` §7, Time row).
5. A `DENY` is a successful evaluation: HTTP 200 with a `Decision` body (`AR` §5.1, "A `DENY` is `200`, on both routes."). Codes for `DENY` causes are listed in the catalog with status 200.
6. The Request type is `PRD` §5: `request_id, request_chain_id, actor_ref, workload_kind, subject_id, model_ref, requested_gpu_count, requested_vram_gb_per_gpu, expected_duration_min, exam_binding (nullable reservation_id)`. The field `node_class_id` appears in `AR` §4.2 (`request.node_class_id`) but not in `PRD` §5: not verified.

## 2. Operation contracts

### Operation: `evaluateRequest(request: Request, idempotencyKey: string, session: SessionActor, derivedFrom?: DecisionId): Decision`

Route: `POST /policy/decisions` (`AR` §5.1). Inputs on the wire: JSON body = `Request`; header `Idempotency-Key`; optional `derived_from` (parent decision id; `AR` §5.1 decisions row, D7). The session actor is injected by the Gateway (`AR` M2-AD-9).

- **Note (ruling DL-50, 2026-10-21):** the order of the rule table of `PRD` §6.2 is not the whole story for these cases: a `DENY` by `R-QUOTA-01` dominates `R-BOUND-01`, and a `DENY` by `R-TIER-01`, `R-TIER-02`, `R-AUTH-01`, `R-AUTH-02`, `R-QUOTA-01` or `R-FLEET-01` dominates `R-FRZ-02`; the overridden `CONSTRAIN` rule is `NOT_EVALUATED` and listed in `suppressed[]`. See `planning/ARCHITECTURE.md` §15.11. The clauses P, Q and I below are not rewritten.
- **Layer:** Inbound Port (use-case `evaluateRequest`, called by the Express route). It orchestrates the Decision Shell and calls the pure `evaluate(request, facts, policy_version)` in Core Domain (`AR` M2-AD-1). Phase 2 confirms.
- **Precondition (P):**
  - P1: body parses against the route wire shape; `expected_duration_min` integer; `requested_gpu_count` integer; `requested_vram_gb_per_gpu` integer; `workload_kind` string; `exam_binding` string or null → violation: `WIRE_SHAPE_INVALID`, HTTP 400, nothing journalled (`AR` §5.1: "`400` wire-shape only (not a `Decision`, not journalled)").
  - P2: header `Idempotency-Key` present and non-empty (`AR` §5.1 "Requires `Idempotency-Key`"; D2). Length and charset: not stated (`review-arch-implementability.md` G-12 stays open) → violation: `IDEMPOTENCY_KEY_MISSING`, HTTP 400 *(identifier assigned here)*.
  - P3: the caller is authenticated; the Gateway supplies a session actor (`AR` M2-AD-9: "every route requires an authenticated caller") → violation: `UNAUTHENTICATED` *(status not stated)*.
  - P4: no stored `IDEMPOTENCY_KEY` row with the same `(actor_id, key)` and `replay_window_expires_at <= campus_now` → violation: `IDEMPOTENCY_KEY_EXPIRED`, HTTP 409, the client sends a new key (K3); and no stored row with the same `(actor_id, key)` and a different `request_hash` (`AR` M2-AD-8) → violation: `IDEMPOTENCY_BODY_MISMATCH`, HTTP 409. `request_hash` is the SHA-256 of the canonical JSON (keys sorted, no whitespace) of `actor_ref, workload_kind, subject_id, model_ref, node_class_id, requested_gpu_count, requested_vram_gb_per_gpu, expected_duration_min, derived_from`; `request_id` and `request_chain_id` are excluded (triage decision D12).
  - P5: `derived_from`, when present, names a stored `DECISION` whose `depth = 0` (the new decision then has `depth = 1`, `AR` §4.1 `CHECK (depth <= 1)`) → violation: `DERIVED_FROM_INVALID` *(identifier assigned here; status not stated)*.
  - P6: `FreezeState` is readable (`AR` §2.1.1: "a read failure is `503` with a problem-details body and **no** `Decision` is recorded") → violation: `FREEZE_STATE_UNREADABLE`, HTTP 503.
  - P7 (decided inside the walk by `R-VALID-01`, precedence −1, `PRD` §6.2): `actor_ref` equals the session actor; every enum is a member of its closed set; `expected_duration_min ∈ [1, 4320]`; `requested_gpu_count ∈ [1, 2]`; `requested_vram_gb_per_gpu ∈ {24, 48}` (`PRD` FR-1) → violation: `DENY` with `cause = INVALID_REQUEST`, `primary_rule_id = R-VALID-01`, journalled. For `actor_ref` ≠ session actor the response is HTTP 200 with that `Decision` (`DENY`, `INVALID_REQUEST`, `R-VALID-01`, journalled); there is no `403` (K1).
  - P8 (`R-VALID-01`): `model_ref` resolves in the catalogue; `actor_ref` resolves; a non-null `exam_binding` resolves to an `ACTIVE` reservation of the request's `subject_id` whose window covers `campus_now`, and the actor holds an entitlement to that `subject_id` (`PRD` §6.2 row −1) → violation: `DENY` with `cause ∈ {MODEL_NOT_FOUND, ACTOR_UNKNOWN, INVALID_REQUEST, NOT_AUTHORIZED}`, `primary_rule_id = R-VALID-01`, HTTP 200.
  - P9 (`R-DEP-01`, precedence 0): every port classified `FAIL_CLOSED` answers within `FACT_TIMEOUT_MS = 40` with a schema-valid body no older than its admission tolerance; every `ADMISSION_STALE_TOLERANT` port has a value no older than its tolerance; the clock reading, when the `Clock` port returns one, has `stratum < 15`, `leap_indicator = 0`, a non-negative age, and an instant not earlier than the last accepted reading (`AR` §2.1.1) → violation: `DENY` with `cause = DEPENDENCY_UNAVAILABLE`, `primary_rule_id = R-DEP-01`, `retry_after_ms = 2000`, HTTP 200. A `Clock` port that returns no instant at all is not a P9 violation: no `Decision` can be dated, and Q-fail applies (triage decision D2).
- **Postcondition (Q):**
  - Q1: returns HTTP 200 with a `Decision` (`PRD` §5.1) in which: `outcome ∈ {ALLOW, DENY, CONSTRAIN}`; `admission = REJECTED` ⟺ `outcome = DENY`; `admission = QUEUED` ⟺ `outcome = CONSTRAIN` and some constraint has `kind = QUEUE_ONLY`; every other result has `admission = ADMITTED`; `authority = PROVISIONAL` iff the decision carries a `QUOTA_CAP` constraint, else `FINAL`; `primary_rule_id` non-null and present in the registry; `cause` non-null iff `outcome = DENY`; `rationale` non-empty; `valid_until` non-null for `ALLOW` and `CONSTRAIN` and later than `evaluated_at`, except the past-bound guard of `prd.md` NP-9 (an `ALLOW` with `valid_until = evaluated_at`, ruling DL-54, `ARCHITECTURE.md` §15.12); `must_checkpoint_by`, when non-null, equals `valid_until`; `next_actions[]` has at least 1 entry for `DENY`, or the sentinel `NO_ALTERNATIVE_AVAILABLE`; `trace[]` and `evidence_snapshot_ref` are embedded in the body (D6); `parent_kind = ROOT` when `derived_from` is absent and `DERIVED` when present; `submitted_by = HUMAN`; `policy_version` is the integer `published_seq` (D8).
  - Q2: in one transaction the module inserts one row each into `DECISION` and `FACT_SNAPSHOT`, and zero or more rows into `TRACE_ENTRY`, `CONSTRAINT`, `SUPPRESSED_RULE`, `DECISION_CITATION` (`AR` §4.2, "The append is one transaction"), plus one `IDEMPOTENCY_KEY` row (`actor_id`, `key`, `request_hash`, `decision_id`, `created_at`, `replay_window_expires_at = created_at + 24 h`) and one `DECISION_OUTBOX` row (`outbox_id` uuid7, `event_type = policy.decision.v1`, `decision_id` set, `failure_id` null; K4). `DECISION.evaluated_at = FACT_SNAPSHOT.campus_now` and `DECISION.depth ≤ 1`. No `UPDATE` or `DELETE` is issued on any of these tables (`AR` M2-AD-8).
  - Q3: the outbox publishes the event `policy.decision.v1` (at-least-once, consumers idempotent on `decision_id`; `AR` §5.2). A `Decision` with `must_checkpoint_by` non-null also creates the obligation toward M9 (`AR` §2.1: `SHELL ==> M9`); the obligation has no event name in `AR`: not verified. Metrics named in `AR` §5.3 and §2.1.1: `journal_lag`, `journal_overshoot`, `fact_aborts_total`.
  - Q4: explainability payload: `primary_rule_id`; `citations[]` ⊆ `POLICY_DOCUMENT.doc_id` (at least 1 entry); `trace[]` with every one of the 19 rules in state `MATCH`, `NO_MATCH` or `NOT_EVALUATED` (every rule below the terminal rule is `NOT_EVALUATED`); for each boundary in the set `B` one `bound_role ∈ {governing, superseded, outside_horizon}` with exactly one `governing`; `suppressed[]` for each `NOT_EVALUATED` rule whose predicate was satisfiable; `stale_facts[]` for each port past its display tolerance; the first sentence of the rationale names the rule id and, for `DENY`, the `cause` (`PRD` FR-9).
  - Q-fail: for P1, P2, P3, P4, P5 no row is written to any table and no event is published. For P6 and for a shell failure before a `Decision` exists, no `Decision` row is written and the module appends the event `policy.decision.failed.v1` (`AR` §3, §5.2); that record is a `DECISION_OUTBOX` row with `event_type = policy.decision.failed.v1`, `failure_id` set and `decision_id` null (K4). For P7, P8, P9 the outcome is a `Decision` and Q1–Q4 hold. When the `Clock` port returns no instant at all, no `Decision` row, no event and no `DECISION_OUTBOX` row is written, because there is no instant to date them; the route answers HTTP 503 `DECISION_NOT_PRODUCED` with `failing_port = campus.clock`, and telemetry raises an alarm (triage decision D2; this carve-out of `DECISION_NOT_PRODUCED` is confirmed by the Architect on 2026-10-20 (G-09)).
- **Invariant (I):**
  - I1: `evaluate()` is a pure function of `(request, facts, policy_version)`; it performs 0 reads of the clock, the network, the file system, and 0 random draws. Bound to: AD-1.
  - I2: every `Decision` has exactly one `primary_rule_id`, in the registry; every rule below the terminal rule is recorded `NOT_EVALUATED`, never `NO_MATCH`. Bound to: AD-1.
  - I3: `admission` and `authority` follow the equivalences in Q1 for every `Decision` the constructor accepts. Bound to: AD-1 (`AR` M2-AD-1 Binds: "the `Decision` constructor").
  - I4: `valid_until` is non-null and later than `evaluated_at` for every `ALLOW` and `CONSTRAIN`, except the past-bound guard (`prd.md` NP-9, lines 393 and 514), which returns an `ALLOW` with `valid_until = evaluated_at` and a `WINDOW_SCOPE` constraint (ruling DL-54, `ARCHITECTURE.md` §15.12); `must_checkpoint_by = valid_until` whenever non-null; `evaluated_at` is the single instant read from `campus.clock` before any other fact fetch. Bound to: AD-3.
  - I5: every fact port that can change `outcome`, `admission`, `valid_until` or a constraint has an admission tolerance in the register; a breach yields `R-DEP-01` inside the walk, never a second code path. Bound to: AD-4.
  - I6: every emitted constraint has a non-null `enforced_by`; `HARD_DEADLINE`, `QUEUE_ONLY` and `QUOTA_CAP` carry a non-null `deadline`; this module holds no client for a mutating method of another component. Bound to: AD-5.
  - I7: every `Decision` has at least 1 `citation_id` that resolves in `POLICY_DOCUMENT`; the rationale is built from `rationale_template[primary_rule_id]` and matched evidence with 0 model calls. Bound to: AD-6.
  - I8: one `policy_version` is read from start to finish of one evaluation; the version, `content_hash`, `engine_version`, `campus_tz` and `tzdata_version` appear on the `Decision`. Bound to: AD-7.
  - I9: one `(actor_id, key)` yields one `decision_id`; the stored snapshot contains actor ids and none of: names, addresses, tokens, keys. Bound to: AD-8.
  - I10: `Request.actor_ref` equals the session actor or the result is `DENY(INVALID_REQUEST)` by `R-VALID-01`. Bound to: AD-9.
- **Concurrency / idempotency:** two simultaneous calls with the same `(actor_id, key)` and the same `request_hash` produce 1 `decision_id`, 1 `DECISION_OUTBOX` row, 1 `policy.decision.v1` event; the second call returns the stored `Decision` without re-evaluation (`AR` M2-AD-8 test `ad8-idempotence.test.ts`: "three `POST`s with one key produce one `decision_id`"). The same key with a different `request_hash` is `IDEMPOTENCY_BODY_MISMATCH`. Different keys are independent evaluations. A second call with the same `(actor_id, key)` that arrives while the first is still in its transaction waits on the unique constraint, then returns the stored `Decision` (same body hash) or `IDEMPOTENCY_BODY_MISMATCH` 409 (different body); there is no extra code path (K3). `IDEMPOTENCY_KEY` rows are never deleted and stay unique per `(actor_id, key)`; a call whose key row has `replay_window_expires_at <= campus_now` (`created_at + 24 h`) is refused with `IDEMPOTENCY_KEY_EXPIRED` 409 and the client sends a new key (K3).
- **Time:** Clock port `campus.clock`, method `Read() → ClockReading{instant, stratum, leap_indicator, source}`, read once, first; the instant is `evaluated_at` (`AR` M2-AD-3). Window containment uses `[starts_at, ends_at)`; `NIGHT_WINDOW = [22:00, 06:00)` campus-local; `bound = MIN(campus_now + expected_duration_min, b* − PROTECTION_GRACE)` computed on absolute instants with `PROTECTION_GRACE = 300 s` (`PRD` §5.4, §6.3). The fan-out timeout per port is `FACT_TIMEOUT_MS = 40`.
- **Latency budget (NFR):** `PRD` NFR-1: `p99 ≤ 5 ms`, `p50 ≤ 1 ms` at 100 concurrent evaluations, measured on `evaluate()` alone; `PRD` NFR-9: `p99 ≤ 45 ms` for the fact fan-out at 100 concurrent; `PRD` NFR-10: `p99 ≤ 2 ms` per rationale render. An end-to-end budget for the route is not stated in `PRD` §8: not verified.

### Operation: `previewFreeze(draftId: Uuid, session: SessionActor): FreezePreview`

Route: `POST /policy/freezes/preview` (`AR` §5.1). The request body schema is not stated in `AR` §5.1 (a `draft_id` versus the draft body): not verified; this contract uses `draft_id`.

- **Layer:** Inbound Port (use-case `previewFreeze`); it reads the Freeze Aggregate and the fact ports 4, 5 (timetable, reservation) through Outbound Ports and writes `PREVIEW_RUN`. Phase 2 confirms.
- **Precondition (P):**
  - P1: body parses, `draft_id` is a UUID, and every instant in the body is a valid calendar instant (`2026-13-45T99:99:99.000Z` is not) → violation: `WIRE_SHAPE_INVALID`, HTTP 400 (triage decision D16).
  - P2: the caller is authenticated → violation: `UNAUTHENTICATED` *(status not stated)*.
  - P3: caller `role_tier ≥ INSTRUCTOR` with `LAB_OPERATOR` scope (`AR` §5.1, D4) → violation: `ROLE_INSUFFICIENT`, HTTP 403.
  - P4: a `FREEZE_DRAFT` row with `draft_id` exists → violation: `DRAFT_NOT_FOUND`, HTTP 404 *(status assigned here; `AR` §5.1 lists no 404 for this route)*.
  - P5: `campus_now < draft.expires_at` (`expires_at = created_at + 24 h`; `AR` §4.1) → violation: `DRAFT_EXPIRED`, HTTP 409 *(status assigned here)*. The instant `campus_now = expires_at` is not stated by `AR` ("a stale draft is not an armed action"); this contract treats it as expired (Section 6).
  - P6: the consequence computation completes from facts the module holds (`denied_count`, `survivors[]`, `next_protected_window`) → violation: `PREVIEW_UNAVAILABLE`, HTTP 503; activation stays blocked (`AR` §5.1, D1).
- **Postcondition (Q):**
  - Q1: HTTP 200 with `{preview_token: string, denied_count: int ≥ 0, survivors: string[], next_protected_window: instant | null, runtime_snapshot: "AVAILABLE" | "UNAVAILABLE", expires_at: instant}`, where `expires_at = issued_at + 60 s` and `preview_token` carries the `preview_run_id` and is signed with `HMAC(server_secret, draft_id ‖ content_hash ‖ actor_id ‖ issued_at)` (`AR` §5.1, M2-AD-9; triage decision D7). The API exposes `runtime_snapshot` as the enumeration; storage stays boolean in `PREVIEW_RUN` (`true` = `AVAILABLE`, `false` = `UNAVAILABLE`) (ruling N3, P2-RULINGS-3).
  - Q2: one `PREVIEW_RUN` row is inserted with `draft_id`, `actor_id` = caller, `content_hash` = draft hash, `issued_at = campus_now`, `expires_at = issued_at + 60 s`, `consumed_at = NULL`, `denied_count`, `survivors`, `next_protected_window`, `runtime_snapshot`. No `FREEZE` row is created or changed. In the same transaction one `audit_events` row with action `FREEZE_PREVIEW_COMPUTED` is inserted (triage decision D16).
  - Q3: no event is named for preview in `AR` §5.2: not verified.
  - Q4: the response carries the three decision-relevant values (`denied_count`, `survivors[]`, `next_protected_window`); rule ids behind `denied_count`: not stated in `AR` §5.1: not verified.
  - Q-fail: for P1–P6 no `PREVIEW_RUN` row is inserted, no token is issued, no `FREEZE` row changes, and `activateFreeze` for that draft returns `TOKEN_ABSENT`.
- **Invariant (I):**
  - I1: a `preview_token` exists only for a `PREVIEW_RUN` row the server wrote; `curl` cannot forge it without `server_secret`. Bound to: AD-9.
  - I2: `PREVIEW_RUN.actor_id` equals the caller; the token is valid for that actor only (the HMAC covers `actor_id`). Bound to: AD-9.
  - I3: `PREVIEW_RUN.expires_at = issued_at + 60 s` (`PRD` §5.4 `PREVIEW_TOKEN_TTL = 60 s`). Bound to: AD-9.
  - I4: the preview does not write `FREEZE`, `DECISION` or `DECISION_OUTBOX`; it is not journalled and not published (its only audit trace is the `audit_events` row of Q2). Bound to: AD-5 (module writes only its owned tables) and AD-9 (preview is a precondition, not an activation).
- **Concurrency / idempotency:** two simultaneous previews of one draft insert 2 `PREVIEW_RUN` rows with 2 tokens; "Re-previewing refreshes the token" (`AR` §5.1). Whether the earlier token stops being valid: not stated; activation locates "an unconsumed `PreviewRun` with a matching hash inside the window" (`AR` M2-AD-9), so both stay valid until each reaches 60 s; the token carries its `preview_run_id`, so activation selects the right row (triage decision D7). An `Idempotency-Key` for this route: not stated.
- **Time:** Clock port `campus.clock`, read once; `issued_at = campus_now`. The token is valid while `now <= issued_at + 60 s` and expired when `now > issued_at + 60 s` (K5; `AR` §4.1 `PREVIEW_RUN.expires_at` comment: "valid AT 60 s, expired above it"). This closed end is an exception to the half-open convention of Section 1 rule 4, by ruling K5.
- **Latency budget (NFR):** no requirement in `PRD` §8 names a budget for this operation: not verified.

### Operation: `activateFreeze(draftId: Uuid, reason: string, previewToken: string, session: SessionActor): ActivatedFreeze`

Route: `POST /policy/freezes/{id}/activate` where `{id}` is the `draft_id` (`AR` §5.1: "Activate a draft"; success `201 {freeze_id, policy_version}`).

- **Layer:** Inbound Port (use-case `activateFreeze`); it drives the Freeze Aggregate (Core Domain state machine `DRAFT → ACTIVE`) and the repository Outbound Port. Phase 2 confirms.
- **Precondition (P):**
  - P1: body parses; `reason` is a string; `preview_token` is a string; any instant in the body is a valid calendar instant, as in `previewFreeze` P1 → violation: `WIRE_SHAPE_INVALID`, HTTP 400.
  - P2: the caller is authenticated → violation: `UNAUTHENTICATED` *(status not stated)*.
  - P3: caller `role_tier ≥ INSTRUCTOR` with `LAB_OPERATOR` scope, read fresh at activation and not taken from the preview (`AR` §5.1, M2-AD-9, D4) → violation: `ROLE_INSUFFICIENT`, HTTP 403.
  - P4: a `FREEZE_DRAFT` row with `draft_id` exists → violation: `DRAFT_NOT_FOUND`, HTTP 404 *(status assigned here)*.
  - P5: `campus_now < draft.expires_at` → violation: `DRAFT_EXPIRED`, HTTP 409 *(status assigned here)*.
  - P6: `reason` is non-empty (`AR` §5.1 activate row: "`400` no reason") → violation: `MISSING_REASON`, HTTP 400.
  - P7: `draft.ends_at > campus_now` (`AR` §5.1: "activation also requires `ends_at > campus_now`") → violation: `WINDOW_IN_PAST`, HTTP 400, applied only when the window has already ended (`ends_at <= campus_now`; `AR` §5.1 `POST /policy/freezes` row: "`ends_at ≤ campus_now` (`WINDOW_IN_PAST`)"). A draft whose `starts_at` is earlier than `campus_now` is accepted (K2).
  - P8: the module recomputes the HMAC of `preview_token` over `draft_id ‖ content_hash ‖ actor_id ‖ issued_at`, locates the `PREVIEW_RUN` by the `preview_run_id` the token carries, and checks in this order: (1) signature and row: the signature verifies and the row exists, else `TOKEN_ABSENT`; (2) actor: `PREVIEW_RUN.actor_id` equals the caller, else `TOKEN_ACTOR_MISMATCH`; (3) expiry, as in P10; (4) consumption, as in P9; (5) stale draft hash: the draft hash recomputed now equals `PREVIEW_RUN.content_hash`, else `TOKEN_STALE`; each violation HTTP 409 (triage decision D7) (`AR` §5.1: "`409` token absent, expired, or stale against the draft hash"; the actor code is assigned here).
  - P9: that `PREVIEW_RUN` has `consumed_at = NULL` → violation: `TOKEN_CONSUMED`, HTTP 409.
  - P10: that `PREVIEW_RUN` is inside its window: `campus_now <= issued_at + 60 s` (K5) → violation: `PREVIEW_EXPIRED`, HTTP 409.
  - P11: after the closing step of Q2 has set the expired ones to `EXPIRED`, no `FREEZE` with `state = 'ACTIVE'` exists for the same normalised scope key → violation: `DUPLICATE_ACTIVE_FREEZE`, HTTP 409 (`AR` §5.1).
- **Postcondition (Q):**
  - Q1: HTTP 201 with `{freeze_id: uuid, policy_version: int}`; `policy_version` is the `published_seq` in force at `campus_now`.
  - Q2: in one transaction, in this order: the closing step sets `state = 'EXPIRED'` on every `FREEZE` row with `state = 'ACTIVE'`, the same normalised scope key and `ends_at <= campus_now` (it writes no event; triage decision D5); then one `FREEZE` row is inserted with `state = 'ACTIVE'`, `scope`, `subject_ids`, `node_class_ids`, `allowances`, `starts_at`, `ends_at`, `reason`, `activated_by` = caller actor id, `activated_by_role_tier` = tier read at activation, `activated_at = campus_now`, `policy_version`; and `PREVIEW_RUN.consumed_at` is set to `campus_now` (`AR` §5.1: "`consumed_at` is written in the same transaction as the activation"). One `DECISION_OUTBOX` row with `event_type = policy.freeze.activated.v1` and `freeze_id` set (triage decision D3) and one `audit_events` row with action `FREEZE_ACTIVATED` (triage decision D16) are inserted in the same transaction. Either all writes commit or none does. `subject_ids` and `node_class_ids` are written sorted lexicographically with no duplicates (the writer's duty; the unique index is not changed; triage decision D6).
  - Q3: the event `policy.freeze.activated.v1` with payload `freeze_id, scope, subject_ids[], node_class_ids[], starts_at, ends_at, allowance_ids[], activated_by, policy_version, preview_run_id` (`AR` §5.2), published through the outbox row of Q2, at-least-once, consumers Gateway, M9, Observability.
  - Q4: the response carries `freeze_id` and `policy_version` only; the event carries `activated_by` (an actor id, not a name) and `preview_run_id`; `activated_by_role_tier` and `reason` are read through `GET /policy/freezes/{id}`, so a journal row's `freeze_id` resolves to what the freeze was.
  - Q-fail: for P1–P11 the transaction does not commit: 0 `FREEZE` rows are inserted, no `FREEZE` row is closed, `PREVIEW_RUN.consumed_at` stays `NULL`, 0 outbox rows and 0 audit rows are inserted, 0 events are published.
- **Invariant (I):**
  - I1: at most 1 `FREEZE` row with `state = 'ACTIVE'` per normalised scope key (partial unique index `WHERE state = 'ACTIVE'`). Bound to: AD-9.
  - I2: a freeze is activated only against an unconsumed, unexpired, actor-bound `PREVIEW_RUN` whose hash equals the draft hash; one `PREVIEW_RUN` is consumed at most once. Bound to: AD-9.
  - I3: `FREEZE` satisfies `ends_at > starts_at`; `subject_ids` is empty unless `scope = 'SUBJECT'`; `node_class_ids` is empty unless `scope = 'NODE_CLASS'`; `allowances` is non-null and an array. Bound to: AD-9 (`AR` M2-AD-9 Binds: "the `FREEZE` store's `CHECK`s and partial unique index").
  - I4: the role tier recorded in `activated_by_role_tier` is the tier read at activation. Bound to: AD-9.
  - I5: activation changes no table that another component owns (M4 reservations, M8 quota, cluster state). Bound to: AD-5.
- **Concurrency / idempotency:** 8 simultaneous activations of one scope yield exactly 1 response `201` and 7 responses `409` (`AR` §5.1; test `ad9-freeze-concurrency.test.ts`); 3 activations of one draft yield 1 freeze (`sa-5.test.ts`). The decision between racers is made by the partial unique index and a compare-and-swap on the freeze store version, not by a prior read (`AR` §5.1). A repeated call with a consumed token is `TOKEN_CONSUMED`; there is no `Idempotency-Key` on this route in `AR` §5.1.
- **Time:** Clock port `campus.clock`, read once; `activated_at = campus_now`. Freeze liveness is `state ∉ {DRAFT, LIFTED, EXPIRED} ∧ starts_at ≤ t ∧ t < ends_at` (`AR` §4.2). The token is valid while `now <= issued_at + 60 s` (K5; see `previewFreeze` Time). `EXPIRED` is computed from the clock on read; the stored value `EXPIRED` is written only by the closing step of Q2 (triage decision D5), never by a sweep.
- **Latency budget (NFR):** no requirement in `PRD` §8 names a budget for this operation: not verified.

### Notes on the two other freeze routes (not full P/Q/I contracts)

- **`POST /policy/freezes` (create a draft).** Any instant in the body must be a valid calendar instant, else `WIRE_SHAPE_INVALID` (400), as in `previewFreeze` P1. In one transaction the module inserts the `FREEZE_DRAFT` row, one `DECISION_OUTBOX` row with `event_type = policy.freeze.drafted.v1` and `draft_id` set, and one `audit_events` row with action `FREEZE_DRAFT_CREATED` (triage decisions D3, D16).
- **`POST /policy/freezes/{id}/lift` outcomes (triage decision D8).** `200`: the freeze is `ACTIVE`, becomes `LIFTED`; in the same transaction one `DECISION_OUTBOX` row with `event_type = policy.freeze.lifted.v1` and `freeze_id` set, and one `audit_events` row with action `FREEZE_LIFTED`, are inserted. `400 MISSING_REASON`: `lift_reason` empty. `403 ROLE_INSUFFICIENT`. `404 FREEZE_NOT_FOUND`: unknown id. `409 FREEZE_NOT_LIFTABLE`: the freeze is not `ACTIVE` (already `LIFTED`, `EXPIRED`, or never activated), or the id is a draft id; nothing is written.

### Operation: `publishVersion(session: SessionActor): PolicyVersionManifest` (route 14, added 2026-10-21, decision DL-41)

Route: `POST /policy/versions/publish`. It is not one of the 13 routes of `AR` §5.1; `ux/EXPERIENCE.md` line 37 calls it (UX-2). This section states only what `PRD` NFR-7, `AR` §2.2 (Rule Registry), `AR` M2-AD-7, `AR` M2-AD-8 and `AR` §5.2 fix. Everything else is an open point (Section 6, point 12), not a rule.

- **Postcondition (Q):**
  - Q1: success response carrying the manifest `{published_seq, published_at, content_hash, engine_version, campus_tz}` (`VersionManifestDto`). The success status is not stated: Section 6, point 12 (c).
  - Q2: in one transaction (`AR` §5.2 row `policy.version.published.v1`: "in the publish transaction"): one `POLICY_VERSION` row is inserted with `published_seq` equal to the previous `published_seq` plus 1 (trigger `policy_version_seq_next` in both SQL files), `content_hash` a `sha256` over the rule set, `NIGHT_WINDOW`, `PROTECTION_GRACE`, `NEAR_BOUNDARY_DISPLAY_HORIZON`, `CAMPUS_TZ`, `tzdata_version` and `engine_version` (`AR` M2-AD-7 Rule), `immutable = 1`; and one `DECISION_OUTBOX` row with `event_type = policy.version.published.v1` and `published_seq` set. Either both commit or neither does.
